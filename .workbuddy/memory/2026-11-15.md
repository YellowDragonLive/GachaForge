## 收尾验证与修复 · 已完成（同日）

- **cmd 批处理坑（重要）**：`scripts/start.bat` 里 `if errorlevel (...)` 复合块内的 `echo` 文案带圆括号 `(first run only)`，cmd 解析时把 `)` 当块结束，报 `... was unexpected at this time.` 并 exit 255，服务根本没起（后续 502 是代理返回的，误判过）。**规则：批处理复合块内一律不写圆括号**，整份脚本 3 处 echo 文案已改成 `-` 分隔。
- **冒烟隔离（设计决策）**：原 `smoke_test.py` 用 TestClient 直连正式 `data/gacha.db`，会往用户画廊写测试抽卡/任务/占位图。现改为：import 应用前把 `GACHA_DB_PATH/OUTPUTS_DIR/THUMBS_DIR` 指向 `%TEMP%/gacha_smoke_*`，用 SQLite backup API 复制正式库但**清空运行时表**（只复用卡池/配方/预设），结束 `engine.dispose()` + 删临时目录。实测跑前后正式库 6 表行数完全一致、27/27、无残留。
  - 附带坑：`with sqlite3.connect(...) as con` **只提交事务、不 close()**，模块级变量持有句柄会让 Windows 上 `shutil.rmtree` 静默失败，必须显式 `close()`。
- **图片接口白名单**：`api/images.py::_safe_file()` 原本只放行项目根，导致输出目录配到项目外（大图放别的盘很常见）时画廊原图/缩略图全 404；也是冒烟隔离后首轮 25/27 的原因。改为放行 `项目根 + GACHA_OUTPUTS_DIR + GACHA_THUMBS_DIR`，路径穿越仍被挡。手册 §4/§5 已同步。
- **验收数据**：`start.bat` 一键启动实测通过（离线自动切 mock）；直连 11 端点全 200；真实服务端到端 **20/20**（抽卡→任务 succeeded 100%→原图/缩略图 200→SSE→静态资源→错误结构）；走 HTTP_PROXY 的 8 端点同样全 200；`smoke_test.py` 27/27。
- **交付状态**：正式库先备份到 `data/backups/gacha_20261115_182354.db`，再清空全部测试残留（会话/抽卡/任务/图片/日志 + 7 个占位图），保留 568 池 / 32490 条 / 3 配方 / 1 预设 / 6 导入批次，画廊从空开始。`.gitignore` 补了 `data/backups/`。本轮 5 个独立 commit，工作区干净。
