## 画师过滤没进 prompt（已修）
- 根因：过滤 chip 的语义是「筛已有槽位的条目」，**不会新增槽位**；内置配方「画师图鉴探索」(id=2) 的槽位只有 `自然景观-花卉` + `角色` + template，所以点「画师:bowalia」时画师池虽被筛过，配方根本不抽它，prompt 里一个画师 tag 都没有，且无任何提示。
- 修法：`backend/app/services/draws.py::_auto_slots_for_filter` —— 表单里带 `池:` 前缀的条件，若配方槽位解析不到对应池，就自动补一个 `count=1, filter=tag` 的槽位；补的是本次执行副本并写进会话快照（同 seed 复现一致），同时给一条「已自动补入」warning。前端 `widgets.js::missingFilterSlots` 把类别名/具体池名折算成 kind，提前在过滤区提示。已有对应槽位时不重复补。

## 装配面板：左侧「游戏人物状态」（新概念，已落地）
- 用户提出：抽卡台左侧应该是**类似游戏人物状态的面板**，通过它选「无人 / 单人 / 多人」「场景」「画风」「衣着」「装备」。我给了三个方案（即席装配 / 队伍编制 / 装配即配方），用户拍板：**「多人目前可以变成配置多个单人，这样就不会乱」，并「拆分成 场景 人物」**。这比我的三个方案都干净——人数不再是开关，而是**人物卡的张数**。
- **关键事实（决定了整个方案）**：人数被焊死在角色条目里。15193 个角色条目中 6406 条自带 `1girl`、1375 条自带 `1boy`，而 `2girls` **只有 1 条**、`multiple girls` **0 条**。所以连抽两次拿到两个 `1girl, xxx` 角色，拼出的 prompt 是 `1girl, 1girl`，模型永远只画一个人——**「多人同框」在旧机制里没有任何入口**。这正是用户要这个面板的根因。
- 解法：`Slot.pick` 锁定到具体条目（按 label 匹配，不吃 filter）、`RecipeDefinition.count_tags` 在 fixed_head 之后注入人数、`strip_count_tags` 把条目自带的 `1girl/1boy/2girls/solo/no humans` 一律剥离（正则 `^(?:\d+\+?|multiple|no)\s*(?:girl|boy|other|human)s?$|^solo(?:\s+focus)?$`）。人数由面板按卡张数 + 性别推导：0 张 `no humans`、2 女 `2girls`、1 女 1 男 `1girl, 1boy`、3 人以上追加 `multiple`。
- 前端：左栏两个页签（场景 / 人物·N）；场景三格（背景/画风/构图）、人物六格（角色/发型/表情/衣着/装备/动作）；**每格三态**——虚线=随机（每抽重摇）、实线蓝框=锁定（每抽不变）、淡色=关闭。点格子展开条目选择器（换池 / 搜索 / 点条目即锁）。人数 = 卡片张数，可复制 / 移除 / 单独设性别；锁角色时按条目里的 `1girl/1boy` 自动校正性别。
- **两个设计决策值得记住**：① 装配有内容时**忽略配方与全局过滤**（两者同时生效会互相筛空，最难排查），原配方/过滤/概念探索收进「改用配方抽卡」折叠区，能力不删只降级；② **装备格默认关闭**——物品类下 69 个池混着食物厨具（实测随机抽出 `sausage`、`oven mitts`、`m&m's`），默认随机只会拉低质量，要装备让用户点开搜 `sword/hat/glasses`。
- 新增接口 `GET /api/pools/items?kind=&q=&pool=`：返回条目本身（label + tags + 池名）。不能复用 `/api/pools/tag-suggest`，因为后者刻意跳过带逗号的长 label（防被 `池:tag` 表达式切碎），而 `pick` 需要原样长 label。
- 验收：`smoke_test.py` 76/76、`test_frontend.mjs` 36/36（新增 4 项装配契约）、端到端 8 项全过（3 抽都含两个锁定角色、每抽只有一个 1girl/1boy、同 seed 逐字复现、换 seed 随机格重摇、锁发型后另一人仍随机、无人只有场景）。提交 `063cc4e`（后端能力）、`0ef8820`（条目接口）、`cd596da`（前端面板）。

## 游戏化：人物状态栏 + 任务卡（用户：「你要模仿游戏的任务状态栏」「把抽卡做出一个很像游戏的界面」）
- 用户两次追加：①「可以跟图直接对比」②「任务卡片 / 把抽卡做出一个很像游戏的界面」。落点是：左栏状态栏**必须有立绘**，右栏一抽一张**任务卡**，两者并排就能对照。
- **立绘数据链路（这轮唯一的硬障碍）**：概念的 key 是英文 tag 小写（`signora (genshin impact)`），而条目 `label` 是中文（`艾比蓋兒·威廉斯 (旅行服) (Fate/Grand Order)`）。所以立绘必须走条目的 `tags`：`1girl, artoria pendragon \(fate\), fate \(series\)` → 剥掉人数 tag 取第一个 → 去反斜杠 + 压缩空白 + 小写。新增 `splitTags / stripCountTags / conceptKeyOf / portraitKeys / personTitle` 五个纯函数（前端版剥离正则与后端 `strip_count_tags` 同一套语义）。候选最多 3 个，逐个试到 found 为止。
- **顺手修了一个真 bug**：锁角色时的性别自动校正原来拿 `label` 匹配 `1girl|1boy`，而 label 是中文 → 从来没生效过。改成对条目 `tags` 里 girls/boys 计数比较。注意**不能用 stripCountTags 的结果**去做这件事（它恰好把 1girl/1boy 剥掉了）。
- **立绘是「按需悬浮」的唯一例外**：常驻一张。代价是每张人物卡一次 `/api/concepts/cover` 请求，按 key 缓存；生图成功（SSE succeeded）时清 `state.portraits` 并重载，这样「刚出的图」能立刻成为立绘。没出过图的新角色显示「未锁定 / …」占位，不显示破图。
- **任务卡**：卡头 `P01` 编号徽标 + `第 N 抽 / seed / #id` + 状态徽标；顶部 2px 渐变条与编号颜色跟状态走（蓝→绿→红）；生成中进度条加 45° 条纹滚动动画；下半「本抽装配」复用 `slotChips`，`detail[].locked` 存在时给 chip 加 `locked` 样式与「锁」角标（`detail.js` 新增，随机槽位不受影响）。状态变化只刷 `[data-state-for]` 与 `[data-flag-for]`，不重建卡片。
- 布局：左栏 336 → **392px**（88px 立绘 + 六行属性在 336 里会挤成两条）；末尾重新声明 1080px 单列 media，避免后写的 `.draw-shell` 覆盖原 media。

## 纸娃娃：物品(prompt) → 人物部位（用户：「左侧应该有个虚线人物」「类似游戏一样」「场景也应该类似」）
- 需求是**把抽象的槽位画成形状**：一行「发型 随机」看不出管的是哪儿，画到身上一眼就对位。落点：角色铭牌在头顶、左列发型/衣着、中间虚线小人、右列表情/装备、脚下一条动作；场景同理（画面=背景、三色点=画风、画框=构图）。
- 实现分成「纯函数出 SVG」+「CSS 出状态」两层：`widgets.js` 的 `dollFigureHtml(slots,{uid,gender,ghost})` 与 `sceneStageHtml(scene)` 只出结构，每个 `<g>` 带 `data-act="asm-open" data-key=…`，**点身体部位复用同一套事件处理器**（`asmOpenPicker`），不新增分支。三态全写在 CSS（`.doll-zone.m-locked/.m-off`），另有一层 `.doll-body` 底稿——否则「表情/装备/动作」三个默认关闭的格子会让身体缺几块，看起来像一坨虚线。
- 两个踩过的坑：① 底稿最初把 path 数据直接拼进 `<g>` 字符串（没包 `<path>`），浏览器当文本丢掉 → 双臂双腿整段消失；② SVG 里的百分比高度在自动高度的 flex 父级里会造成「intrinsic 反推高度」，把整张卡撑高，改成绝对定位后才稳定。还有 **`vector-effect: non-scaling-stroke` 必须挂在图元上**（`.doll-svg *`），否则画框放大 2.27 倍后 1.5px 描边变成 5px 的粗虚线。
- 修了一个一直没人发现的真 bug：`asmSceneHtml` 从来不输出 `asmPickerHtml`，所以场景页签点格子后条目列表永远出不来（`$('.asm-entries')` 为 null）。现在补上，并给选择器加了标题「背景 · 选条目或改状态」，点身体部位时也知道自己在改哪一格。
- 立绘顺势改成**铺在小人底下当底图**（`.doll-art` 是整块按钮，点空白/照片进概念详情页；点身上那一块=换那一格）。有图时描边转白色 + `drop-shadow(0 0 1px rgba(15,22,40,.55))`，浅色照片上也读得出来；「立绘」二字缩成左下角小角标，不再遮挡图形。
- 格 ↔ 部位双向高亮用纯 CSS `:has()`：`.char-body:has(.part[data-key="hair"]:hover) .doll-zone[data-key="hair"]`，零 JS 零重绘。
- 验证方式值得保留：**Chrome headless + CDP（Node 22 自带 WebSocket，零依赖）**驱动 `Page.navigate / Runtime.evaluate / Input.dispatchMouseEvent / Page.captureScreenshot`，脚本在 `%TEMP%/shot.mjs`，能点格子、选条目、切页签并逐屏截图。注意两点：① 页面只在 `Page.reload({ignoreCache:true})` 后才拿到新 CSS（否则测的是旧样式，会误判 `:has()` 不生效）；② 每次先 `sessionStorage.clear()` 再 reload，否则上一轮的卡片会留在装配状态里。
