## 前端选不到 MOSS：两套模型目录被当成一套枚举

**用户现象**：在「生成参数预设」的 checkpoint 下拉里搜 `moss`，什么也搜不到。

- **根因**：ComfyUI 里 `UNETLoader.unet_name`（扫 `models/unet` +
  `models/diffusion_models`）和 `CheckpointLoaderSimple.ckpt_name`（扫 `models/checkpoints`）
  是**两个目录、两套枚举**。`/api/comfy/models` 只枚举了后者，前端也只读
  `models.checkpoints`。Anima 之所以"碰巧"能选，是因为 `link_unet_models.py` 把它的文件
  硬链接到了两个目录；MOSS 没建链接，就彻底看不见。
- **修复**：`WorkflowRegistry.ckpt_kind(name)` 读模板里 `$CKPT` 落在哪个 class_type 上
  （`UNETLoader` → `unet`，其余 → `checkpoint`），随 `/api/config` 下发；
  `/api/comfy/models` 加 `unet` 列表；前端唯一出口 `ckptPoolKey(state, workflow)`。

**换 workflow = 换模型族，五项必须一起换**（否则必然报错或出废图）：

| 项 | 不换的后果 |
|---|---|
| checkpoint | 纯 UNet 名喂给 CheckpointLoaderSimple 报 `Could not detect model type` |
| CLIP | Anima 用 qwen 0.6B、MOSS 用 qwen3.5 9B，维度不对 |
| VAE | 潜空间不兼容 |
| steps / CFG | turbo 模型用 CFG 5 会烧成色块 |
| LoRA | 绑在具体底模上，跨族挂着只污染画面 |

默认值来源：spec 的 `params.*.default`（`/api/config` 以 `defaults` 下发）。
`moss.spec.json` / `anima.spec.json` 的 `CKPT` 都补了 default，所以预设留空也能跑。

**教训**：`Number(undefined) ?? x` 得到 `NaN` 不是 `x` —— 可空数字要用
`Number.isFinite(Number(v))` 兜底，`??` 只认 null/undefined。

## start.bat 双击闪退（2026-11-17 修）

用户报双击闪退。复现输出：uvicorn `ERROR: [Errno 10048] ... bind 127.0.0.1:8765`，
随后 bat 直接 `goto :eof` 关窗——**8765 上旧服务还在跑，第二个实例绑不上端口**，
而 bat 对 `run_server.py` 没有 errorlevel 检查，错误来不及看就没了。

修法：
- 新增 `scripts/probe_server.py`（TCP 探测配置端口，0=已在跑 / 1=没在跑，`--open` 顺手开浏览器）。
  `start.bat` 起服务前先探测：已在跑就提示 + `pause`，要换代码需先关旧窗口。
- `run_server.py || goto :fail`；`:fail` 有 pause，任何失败都停住让人看。
  `GACHA_NO_PAUSE=1` 供自动化跳过 pause。
- **两个 bat 固定 CRLF 行尾**：LF-only + 多行 `if (...)` 块会让 cmd 把行的前半截当命令
  （实测报 `'omfyUI' 不是内部或外部命令` 等）；中文 REM 也会被拆错，改英文注释，
  多行 if 块换 `goto` 标签。中文只放 `echo` 里。

判据：改完用 `GACHA_NO_PAUSE=1 cmd.exe //c scripts/start.bat` 复测，应打印
`Server is already running` 并干净退出；冒烟 136/136。commit `8fc72ca`。

### 用户否掉「提示先手动关窗」：改成 kill-then-start（同日再修）

**用户原话**：「真正的问题是你启动的东西我无法关闭也无法感知状态」→ 收敛成
「没必要，把 start.bat 改成会清空上一个占用的程序就行 kill sth than start」。
所以「已在跑就 pause 让人手动关旧窗口」不是他要的——他要双击一次就换成一个新的、
由他自己双击出来的、有窗口可 Ctrl+C 关的实例。**别再替用户后台起服务**：从工具里
用 `run_in_background` 拉起的服务挂在 WorkBuddy 的 bash.exe 下，桌面无窗口，正是
「无法关闭/无法感知」的来源。验证完要把后台任务停掉，让他自己双击。

最终方案（最小改动，没新增文件）：
- `probe_server.py` 加 `--kill`：netstat 找配置端口的 LISTENING PID，**只杀命令行含
  `run_server.py`/`uvicorn` 的进程**（防误杀 ComfyUI），taskkill /F 后轮询等端口释放；
  被别的程序占了就退出 1，不替用户做主。
- `start.bat` 起服务前无条件 `probe_server.py --kill`，`errorlevel 1` 走 `:fail`；
  删掉旧的「已运行就 --open + pause + 退出」分支。保留 `title Gacha Server - ...`。
- netstat 输出是本地编码，`subprocess.run(text=True)` 在这台机器抛
  `UnicodeDecodeError`（0xbb）——用 `capture_output` 拿 bytes 再 `.decode(errors="replace")`。
  taskkill 的中文成功提示是 GBK，同样防御式解码，乱码只影响打印不影响逻辑。

实测：服务 PID 2252 在跑时再双击 → 日志 `[kill] stopped old server pid 2252`、
`port 8765 free - ready to start`，新实例干净起来，无 10048。冒烟 136/136、前端 66/66。
