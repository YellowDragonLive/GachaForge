# 2026-11-17

## 池内切片（facet）：用户否掉了「随便改池子」，指出真需求是「细化池子」

**用户原话**：「我感觉 随便改变池子是伪需求，真正的需求是 细化 池子」

### 数据证实的病根（比体感严重）

- `人物-头发` 214 条里混着七个维度：长度 / 束法 / 质地 / 刘海 / **发色** / 性别向 / 适格。
  想「只要长发」「不要光秃」只能整池换掉 → 要么抽到光头，要么把池关掉连发型都没有。
- **细池不是另一批池，就是粗池的子集**：`hair_styles_tied` 45/45、`front` 12/12、
  `length` 9/9、`texture` 9/9 与头发池重叠 **100%**。同一维度做了两套并存，粗的因为
  条目多（`log(条目数)` 加分）排在 UI 前面，用户永远拿到粗的那套。
- 「风格」19 池里 13 个是 `audio_*`（乐器/播放器/曲风）——kind 标错，不是细化问题。
- 「物品」69 池 top5 全是 `food_*` ——「装备」部位推荐出这些，体感「只会拉低质量」。

### 方案：不拆池，给池挂切片轴

拆池会爆池数（568 → 2000+）、不可逆、下个切面还得再拆。改成池与条目一个字不改，
其上挂正交维度：

```
pool_facets       池内一档（group_name='长度', slug='len-long', name='长发'）
pool_item_facets  条目↔切片多对多（bald girl 既是「无发」又是「异常向」）
pool_absorption   被收编的细分池（只隐藏入口，删这行即回滚）
```

规则在 `backend/app/core/facet_rules.json`，入口 `scripts/build_facets.py`。
手册 `docs/运维_池内切片.md`，架构 `docs/架构_总览.md §6.1`。

### 三个必须记住的判据

1. **组内 first-match、组间 AND**：选「长发」+「异常向」= 长发里的非人类。
2. **一组的档合计 ≥ 池总量 → 整组不返回**。一档吃掉 89% 的维度（服装「场合」）
   摆出来等于没得选。但**单档组要保留**（「只要异形瞳」恰恰最有用），别按档数砍。
3. **`catch_rest` 档（「散发」「无刘海」）不落库**。它语义就是「不选」，
   摆成 chip 只是占一行位置——点「无刘海」197 条和不点没区别。

### 收编（用户选「收编成 facet，界面不再单列」）

19 个 danbooru 细化池，先算细池里粗池没有的条目并**补进粗池**再隐藏入口——
只隐藏不补会丢货（实测 `hair_styles_misc` 有 2 条独有：`hair up` / `hair down`）。
`/api/pools` 默认不返回，`include_absorbed=true` 看回来。

### 踩到的坑

- **`from_pool` 要写完整 slug**（`wc:DanbooruTAG/hair_styles_tied`），少 `wc:` 会静默查不到。
- **`DrawSessionIn` 漏 `facets` 字段 → Pydantic 静默丢弃**，实测抽出来还是整池随机。
  加字段前先确认 schema。
- **`pool_facets` 建行要一次给全 NOT NULL**（group_name/name），先建空行再赋值会 IntegrityError。
- **前端横滑 chip 行对 6 维度无效**：一行 354px 只看得见前两个，「适格」（正主）要滑 3 屏。
  改「组名一列 + 档位一列」的网格，档位列内换行，零次滑动。

### 落点优化（不动 rankPools 通用排序）

`asmOpenPicker` 优先落在 `facet_groups > 0` 的匹配池：点「衣着」先看到能按类型细分的
190 条，而不是 740 条一整套、没有切片的「组合预设/服装-女性简单穿搭」。
`/api/pools` 加返回 `facet_groups`（distinct group_name 计数），池 chip 上挂小圆点标记。

验证：冒烟 122/122（新增 9 条 facet 断言）、前端契约 64/64（新增 2 条）、
实机截图四张零页面异常。四个 commit：数据层 / 后端 API / 前端 UI / 文档。

## 抽卡 10 连：facet 实战 + ComfyUI 启动姿势

- **ComfyUI 后台拉起**：`cmd //c start` 在 Git Bash 下 SIGTERM 失败；改用
  `run_in_background` 直跑 `python_embeded/python.exe -s ComfyUI/main.py --windows-standalone-build`，
  20 秒 `:8188/system_stats` 返回 200，10 张 1024×1344/10 步约 **20 秒一张**。
- **建 session ≠ 出图**：`POST /api/draw-sessions` 只落 Draw + 提示词，出图要再
  `POST /api/jobs {draw_ids:[...], gen_profile_id}`（幂等 key = `d{draw}:p{profile}:{workflow}`，
  同参数重提会直接复用旧 Job）。只抽不提交，`/api/jobs` 里永远看不到新任务。
- **facets 真生效**：`facets={'人物-头发':['len-long','len-medium','len-short']}` 三档组内 OR
  = 排掉「无发」3 条（bald / bald girl / skinhead），10 张无一光头。
  但 `适格/异常向` 里的 `spiked hair`、`antenna hair` 仍可能漏进来 —— 长度轴治不了它，
  要排除得在 negative 里写，或加「正常发型」正向档。
- **`人物-面部` 池（230 条）全是 `:q`/`uwu`/`glasgow smile` 之类颜文字与崩坏脸**，
  `人物-眼睛`（64 条）是异形瞳（`no sclera`/`slit pupils`），**不能当「美女」默认槽位**，
  写死 `beautiful woman, detailed face, glossy lips` 才是正解。
- 组合预设「服装-女性简单穿搭」740 条是**整句穿搭**（`Striped top, high-waisted jeans, loafers`），
  一个槽位一条就够，别再叠上衣/下装/鞋袜三个槽。

## MOSS 抽卡（写实真人）

- **预设 #7 的 `checkpoint` 原本是空字符串**，直接跑必然报 unet_name 为空。模型其实早就在
  `UNETLoader` 列表里：`moss_image_sft_turbo_int8_convrot.safetensors`。另外两个必填：
  CLIP `qwen3.5_9b_w4a8_gptq.safetensors`（`CLIPLoader.type` 必须选 **`moss_image`**，
  不是 `qwen_image`）、VAE `flux2-vae_small.safetensors`。
- **CFG=1.0 时 negative 完全无效**（不做无引导对比），想压坏图只能靠正向描述，
  别指望往 negative 里堆词。MOSS 8 步 / euler / simple，832×1216 约 15–20 秒一张。
- **Flux 系吃自然语言，但 danbooru tag 混进去不掉真实感**（实测 `long hair` 类 tag +
  英文穿搭短语 + 摄影参数，10 张全部照片质感）。关键在写死摄影语言：
  `natural skin texture with visible pores, faint freckles, shot on Canon EOS R5 with 85mm f/1.4,
  shallow depth of field, film grain, photorealistic`。
- **HEAD 必须写年龄**（`in her early twenties`）。漏了就会因 `white hair` + 全白穿搭抽出
  中老年女性 —— 这是本轮唯一一张废图的成因。
- 「人文景观-室内」池含 `toilet` / `locker room` / `bathtub`，写实人像会出坐在马桶上的构图。
  写实场景宁可直接写死（`in a sunlit modern apartment`），别用池抽。
- 全身构图手藏在身侧最安全；MOSS 对四肢的处理比 Anima 稳，两批 16 张无一手部崩坏。
