# 架构：模块化拆分与多模型 workflow

> 2026-11-16 架构评审后定稿。本文是**唯一口径**：新增模型、拆分模块、改数据契约都照本文执行。
> 背景：当天经多轮补丁式开发，准备接入 Anima / image 两种不同 workflow，先还债再开发。

## 1. 审核结论：四个断点

三路独立审阅（生图链路 / 前端职责 / 数据模型）结论一致。当前系统的分层意图是对的（`api → services → core → worker → comfy`），
但「workflow」和「意群」两个概念从未成为一等公民，靠字符串约定维持，形成四个断点：

| # | 断点 | 证据 | 后果 |
|---|---|---|---|
| 1 | 意群是字符串 hack | `widgets.js` 把自由词编译成 `pool:"任意值·P1"` | 无归属字段、无实体，后端不认识意群 |
| 2 | 快照不完整 | `services/draws.py` 写 `session_recipe_slots` 只存 `pool/count/weight/filter/template` | `free`/`pick`/`count_tags` 只在 `definition_json`，"同 seed 复现"是假复现 |
| 3 | Job 不记 workflow | `GenerationJob` 表无 workflow / 参数列；`worker.py` 从 session 快照取参数 | 换预设重跑是假覆盖；同一 Draw 用三种模型出图无从追溯 |
| 4 | SDXL 节点焊死 | `comfy.py` 硬编码 `model_src="1"`、14 个占位符白名单、LoraLoader 的 slot 0/1 | 加 workflow 必须改 Python 主链路 |

附带确证的问题：`gen_profiles` id=1 已是 Anima checkpoint 配 `sdxl_minimal.json`（错配已发生）；
`services/pools.py` 有两个同名 `list_items`（`:98` 被 `:211` 覆盖，旧端点传位置参数会 `TypeError`）；
Pydantic `extra='ignore'` + `upsert_profile` 白名单形成两道静默丢弃。

## 2. 关键事实：三种模型共用一个 ComfyUI

不需要多 backend。实测三份节点图的-loader 不同，但提交协议完全相同（`/prompt` + `/history` + `/view`）：

| 模型 | 加载节点 | 文本节点 | 采样节点 | 输出节点 |
|---|---|---|---|---|
| SDXL | `CheckpointLoaderSimple`(1) | `CLIPTextEncode`(2,3) | `KSampler`(5) | `SaveImage`(7) |
| Anima | `UNETLoader`(44)+`CLIPLoader`(45)+`VAELoader`(15) | `CLIPTextEncode`(11,12) | `KSampler`(19) | `SaveImage`(46) |
| image | 待接入，按实际节点补 spec | — | — | — |

所以抽象对象是 **WorkflowSpec（工作流规格）**，不是 backend。

## 3. 目标架构

```
workflows/sdxl.json ─┐
workflows/anima.json ├─→ WorkflowSpec 解析器 ─→ 生成服务 ─→ Worker ─→ ComfyUI 8188
workflows/image.json ─┘        （core/ 纯逻辑）      （Job 记快照）
                                    ↑
前端 features/generation.js ────────┘
（workflow / checkpoint / LoRA 选择唯一入口）
```

**加一个新模型 = 加两份文件（节点图 JSON + spec JSON），不改主链路。**

## 4. WorkflowSpec 契约

规格文件与节点图同名、`.spec.json` 后缀，放 `backend/workflows/`。字段：

| 字段 | 含义 |
|---|---|
| `id` / `label` | 稳定标识 / 界面显示名 |
| `template` | 节点图文件名 |
| `params` | 占位符 → 取值来源（`prompt` / `negative` / `seed` / `prefix` / `profile:key` / `lora_chain:slot` / `const:value`） |
| `lora` | LoRA 注入策略：`class_type`、输入/输出槽位、链起点；`null` 表示该模型不支持 LoRA |
| `result_nodes` | 只从这些节点的 `outputs.images[]` 取结果（不再扫全部节点） |
| `capabilities` | `negative` / `lora` / `ref_image` 等能力声明，供 UI 与校验使用 |

参数来源用数据描述代替 Python 白名单：`_resolve` 遇到 spec 里没声明的占位符仍然报错（防呆），
但新增占位符只需改 spec，不改 `comfy.py`。

## 5. 数据层改动（不破坏现有库）

原则：**只加表、不改现有表**，让 `create_all` 自动建表，现有库零风险，不需要迁移脚本。

| 新表 | 用途 | 解决的断点 |
|---|---|---|
| `profile_params` | 按 `(profile_id, workflow_id, key)` 存模型族专有参数（Anima 的 clip/vae 等） | 断点 4 的参数分包 |
| `job_snapshots` | 每个 Job 记实际使用的 workflow_id + 完整参数快照 + prompt/seed | 断点 3 的假覆盖 |
| `slot_extras` | 按 `slot_kind + slot_id` 存 group_key / mode / free / pick / locked | 断点 1、2 的意群归属与复现 |

`GenerationJob` 表本身不加列；快照通过 `job_snapshots.job_id` 关联。Worker 改为**从 Job 快照取参数**，
不再从 session 现算——这是支持"同一 Draw 分别用三个模型出图"的关键。

## 6. 前端模块边界

零构建 ESM 不变，不引入框架、不引入构建链。`app.js` 从 2397 行降到 300 行的 composition root，
只保留：`refreshBase()`、事件分派（click / input / change / keydown / hover）、`startStream()`、
`boot()`、视图注册、诊断句柄 `window.__gacha`。

**分两层，不按技术角色分（没有 controllers/services 这种空壳）：**

| 层 | 模块 | 职责 |
|---|---|---|
| 内核 | `store.js` (11) | 唯一可变 state 对象，别的模块只能读写字段，不许再导出副本 |
| 内核 | `core/ui.js` (30) | `$` / `view` / `num` / `toast` / `fail` / `done` |
| 内核 | `core/router.js` (78) | `registerView` / `refresh(view)` / `onRoute` / `setNav` / `updateStatus` |
| 视图 | `views/{draw,concepts,pools,recipes,jobs,gallery,settings}.js` | 一个页面一个文件：渲染 + 它自己的动作 |
| 领域 | `features/{assembly,vocab,quickfilter,filter,covers,generation}.js` | 跨页面复用的能力（装配面板、双语补全、快速筛选、过滤构造器、按需悬浮、profile/workflow） |
| 纯函数 | `widgets.js` (1003) / `detail.js` | 零 import 的 HTML 片段与归一化函数，可直接用 data URL 单测 |

**动作注册表（原 338 行 switch 的替代）**：每个视图/领域模块导出一个
`export const actions = { 'data-act': async (btn) => {...} }`，`app.js` 只有一个委派器：

```js
const handlers = { ...coreActions, ...drawActions, ...assemblyActions, ... };
const handler = handlers[btn.dataset.act];
if (handler) await handler(btn);   // 无 handler = 未注册动作，静默
```

跨域动作（`view-retry`、图片评分/收藏要同时改概念页/画廊/抽卡台）留在 `app.js`。

**依赖方向**：`views/* → features/* → (core | store | widgets | api)`；横向依赖只允许
`features/filter → views/concepts`（过滤后要刷概念面板）。**feature 不得 import 视图的 render**，
要重绘统一走 `refresh('draw')`，靠 router 注册表回调，避免循环依赖。

**两道静态闸（都在 `node scripts/test_frontend.mjs` 里）**：
1. `data-act 契约`：全前端产出的 `data-act` 集合 ⊆ 全前端注册表键集合；input/select 的动作由
   `dataset.act === 'x'` 分支认领。反方向也查（注册了但没人产出 = 死动作）。
2. `引用契约`（`scripts/frontend_refs.mjs`）：模块里**调用**的每个函数必须有来源（本模块声明 /
   import / 内置）。`node --check` 只验语法，漏 import 要等用户点到那个按钮才炸——实测踩过两次
   （`restoreFormState` 让整个 boot 抛错、所有视图空数据；`refresh` 让卡池开关点了就报错）。

**验收必须真跑**：契约测试通过 ≠ 页面能用。改完前端固定跑 CDP 探针（读 DOM 与 `state` 计数，
不看截图），至少确认六视图渲染、`state.pools/recipes` 有数、实抽能出卡、console 零 error。

## 7. 如何加一个新模型（SOP）

1. 把 ComfyUI 的节点图存为 `backend/workflows/<id>.json`，把需要注入的字段改成 `$PLACEHOLDER`。
2. 写 `backend/workflows/<id>.spec.json`：声明 `params` 来源、`lora` 策略、`result_nodes`、`capabilities`。
3. 若该模型有专有参数（如 clip/vae 文件），在前端 generation 模块加对应输入，值存 `profile_params`。
4. 刷新页面：`/api/config` 自动下发新 workflow 列表，选择器里即可选。
5. 冒烟：用该 workflow 提交一条 Draw，确认出图与结果解析。

**不需要改**：`comfy.py`、`worker.py`、`generation.py`、数据表结构。

## 8. 兼容与回滚

- 现有 `sdxl_minimal.json` 保留原名，`sdxl.spec.json` 指向它——老预设的 `workflow` 字段无需改。
- 无 spec 的 workflow 文件按 SDXL 兼容模式处理（老数据不炸），并在 `/api/config` 标 `spec: false`。
- 每次拆分独立 commit，测试用临时库；出问题按 commit 回退，不动用户配置。
