# 运维：池内切片（facet）

一个池装了好几个维度时，用切片把范围收到「这一档」，而不是拆池、也不是给池子加排除语法。

## 固定命令

```bash
python scripts/build_facets.py                      # 只算不写，打印每池每组的分布
python scripts/build_facets.py --apply --absorb     # 写库（幂等，可重复跑）
python scripts/build_facets.py --pool 人物-头发 -v   # 只看一个池，打印未归类条数
```

`--absorb` 会顺手把与粗池重叠的 danbooru 细分池标记为「已收编」（界面不再单列）。
写库前先 `python scripts/backup_db.py`。

## 给一个新池加切片

1. 打开 `backend/app/core/facet_rules.json`，在 `pools` 数组里加一项：

   ```json
   { "pool": "wc:人物-头发", "fields": ["tags", "label"],
     "groups": [ { "name": "长度", "sort": 10, "options": [
       { "slug": "len-long", "name": "长发", "match": "\\b(long|waist length)\\b" },
       { "slug": "len-saloon", "name": "不论", "catch_rest": true } ] } ] }
   ```

2. 三个必须知道的点：
   - `pool` 写**完整 slug**（`wc:` 前缀不能省），写池名查不到会静默跳过。
   - 组内 **first-match**：按 `options` 顺序，命中第一个就停，所以把更具体的放前面
     （`long bob` 想归「长发」就把长度放 `bob` 前面）。
   - `catch_rest` 是「本组剩下的都归我」，它**不落库、不出 chip**——语义等于「不选」。
     它只用来让覆盖率算得准，别指望用户在界面上点到它。

3. 跑 dry-run 看分布，确认每档条数合理（某一档 0 条会被自动跳过）。

4. `--apply` 写库，然后刷新页面。

## 怎么判断一个维度值不值得做

| 判据 | 说明 |
|---|---|
| 档合计 < 池总量 | 必须能真正切掉一部分，否则整组不返回给前端 |
| 非 catch_rest 档 ≥ 1 | 单档组（「只要异形瞳」）恰恰最有用，别按档数砍 |
| 最大档不是 89% 的「其他」 | 那种维度等于没做，先补规则或换维度 |

## 收编细分池

在 `absorb` 数组里加 `{"pool": "wc:DanbooruTAG/xxx", "into": "wc:人物-头发"}`，
跑 `--apply --absorb`。脚本会先算出细池里粗池没有的条目并**补进粗池**，再隐藏入口——
只隐藏不补会丢货（实测 `hair_styles_misc` 有 2 条独有）。

**回滚**：`DELETE FROM pool_absorption WHERE pool_id=<细池 id>;` 细分池立刻回到池列表，
粗池多补的那几条留着无害（与原有条目重复的会被 `content_hash` 认出来）。
