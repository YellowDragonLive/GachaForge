# 架构总览

> 本文是**结构问题的唯一入口**：想弄清「东西在哪、为什么这么放、加东西该改哪」先看这里。
> 操作步骤看 `运维_启动与验收.md`，数据搬迁看 `运维_数据迁移.md`。
> 结构与本文不一致 = 有一个没写进文档的改动，先改文档再改代码。

---

## 1. 它是什么

一个**单机单人**的抽卡生图工作台：把 Danbooru 词卡抽成 prompt，交给本机 ComfyUI 出图，
再把出过的图反哺成「概念」索引，供下一次按图选词。

三个特征决定了所有设计取舍：

| 事实 | 后果 |
|---|---|
| 只有一个人用、只监听 `127.0.0.1` | 不做登录、不做权限、不做多租户；`GACHA_TOKEN` 只是逃生口 |
| 本机已有 ComfyUI 与权重 | 不联网、不调云端 API、没有 API key；出图走 `127.0.0.1:8188` |
| 双击 `start.bat` 就要能跑 | 不引构建链：没有 npm / Vite / .vue / 打包步骤 |

## 2. 技术栈

| 层 | 选型 | 为什么是它 |
|---|---|---|
| 语言 | Python 3.13（`3.13.12` / `3.13.14` 均在用），前端纯 ESM JS | 抽卡算法原本就是 Python；前端不需要编译 |
| Web | FastAPI 0.163 + Uvicorn 0.54 + Pydantic 2.14 | 自带边界校验与 OpenAPI；单人工具不需要更重的框架 |
| 数据 | SQLite（WAL）+ SQLAlchemy 2.1 + Alembic 1.20 | 单文件可备份、可直连 sqlite3 排查；换 PG 时 ORM 不用重写 |
| 实时 | SSE `GET /api/jobs/stream` + 任务表轮询兜底 | 只要单向进度；浏览器原生断线重连，不需要 ws 协议栈 |
| 前端 | 原生 ESM + **Vue 3.5.45 全量浏览器版**（`frontend/vendor/vue.esm-browser.prod.js`，177KB，自带模板编译器） | 渐进迁移：视图内部换 Vue，对外导出名不变；双击 `start.bat` 照旧能跑 |
| 出图 | 直连 ComfyUI HTTP API（`/prompt`、`/history`、`/view`、`/object_info`、`/interrupt`） | 抽象对象是**节点图**而不是「后端」，三种模型共用一个 ComfyUI（见 §7） |
| 语义 | 构建期离线算向量（ONNX MiniLM，`vendor/pydeps` 里的 onnxruntime）+ 运行期只做 numpy 余弦 | 不装云端 SDK、不要 key；索引与权重都可重建、不入库 |
| 词表 | `data/vocab/danbooru-cn.json`（33071 条，MIT） | 汉化 = 本地 map，中文永不进 prompt（见 §9.4） |

**依赖不重复下载**：`vendor/pydeps/` 与 `data/models/` 是从本机已有环境搬来的（`scripts/vendor_deps.py`），
`start.bat` 自动挂 `PYTHONPATH`。`requirements.txt` 只列必须 `pip install` 的七个核心包。

## 3. 进程与端口

```
        ┌─────────────────────────────────────────────┐
浏览器  │  python -m uvicorn  （单进程）               │
:8765 ──┤   FastAPI 路由 + 静态托管（NoCache）          │
        │   └─ GenerationWorker：1 个 daemon 线程       │
        │      串行消费 generation_jobs，一次一单        │
        └───────────────┬─────────────────────────────┘
                        │ HTTP
                        ▼
             ComfyUI :8188（独立进程，可选，由 start.bat 拉起）
```

- **只有一个后端进程**。前端由它托管，不存在第二个静态服务器。
- **出图是串行的**：Worker 一次取一个 `queued` 任务，取不到就 `worker_poll`(0.4s) 睡一下。
  这是有意的——单卡机器并行只会互相抢显存。
- **静态资源必须 no-cache**：前后端同进程、改 JS 不重启，否则用户刷新可能拿到上一版 JS，
  表现为「点了没反应」，极难排查。
- ComfyUI 挂了不影响抽卡：抽卡是纯计算，图可以晚点再出；`/api/jobs` 会明确拒绝而不是静默失败。

## 5. 一次抽卡的完整链路

分成**两段**，中间用 `draws` 表隔开。这是理解整个系统的关键：
段一纯计算、可离线、可 mock；段二异步、要 ComfyUI、可重试。

### 段一：抽（同步，毫秒级）

```
输入：会话配置（场景/人物 N 张/画风/构图/配方/LoRA/参数）
  1  前端 views/draw.js 读 store.js 的装配状态
  2  POST /api/draw-sessions
        services/draws.create_session()
          ├─ 装配模式：按意群（场景 / 人物1 / 人物2…）逐格抽词
          │    · 每格 = 池 + 条数 + 权重 + 过滤 + 锁定项
          │    · 人数由面板统一写 count_tags，并剥掉条目自带的计数 tag
          └─ 配方模式：core/recipes.run_recipe() 展开 __池__ 模板
  3  core/pools.draw_pull() 按 seed 抽，同 seed 必然同结果
  4  写 draw_sessions / draw_profiles / session_recipes / session_loras
     写每抽 draws + draw_slots + draw_slot_tags（结构化，不再存整段 prompt 字符串）
     写 slot_extras（group_key / mode / free / pick / locked —— 意群归属与复现）
  5  返回：N 抽，每抽带 prompt、detail（逐条来源）、slot 状态
```

**为什么明细要落成关系表**：旧实现把整个 prompt 存成字符串，「这一条词是从哪个池哪一格来的」
无从查起，于是「同 seed 复现」是假复现。现在 `draw_slot_tags` 记住每一词，`slot_extras` 记住意群，
`job_snapshots` 记住实际参数——三者合起来才能真的重放。

### 段二：出图（异步，几十秒到几分钟）

```
  6  POST /api/jobs  {draw_ids: [...], gen_profile_id}
        services/generation.submit_jobs()
          ├─ 先写 job_snapshots：workflow 名 + 完整参数 + prompt + negative + seed
          └─ 写 generation_jobs（status=queued）→ 立即 202 返回 id
  7  Worker 线程（串行）
        queued → submitted → running → succeeded | failed | dead | cancelled
          ├─ 从 job_snapshots 取参数（**不再**从 session 现算）
          ├─ profile_params 里按 (profile_id, workflow_id) 合入 clip/vae 等模型专有参数
          ├─ core/workflow 按 spec 把 profile 映射成节点图占位符
          ├─ ComfyClient.submit() → /prompt
          ├─ wait_result()：轮询 /history，把 step/total 推给事件总线
          └─ images.save_result()：下载 /view → 落 data/outputs → 生成缩略图 → 注册 images
  8  进度经 SSE /api/jobs/stream 推回前端；任务卡只刷状态位，不重建整张卡
```

**为什么快照要存在 Job 上**：同一抽可以用 SDXL 出一次、Anima 再出一次，各带各的参数。
快照挂在 Job 上，重跑才是「用这套参数再跑一遍」，而不是「用当前会话的参数跑」——
后者正是旧的假覆盖 bug。

## 6. 数据模型

22 张表，按用途分五组。全部定义在 `backend/app/models.py`，不拆文件。

| 组 | 表 | 说明 |
|---|---|---|
| **字典** | `pools` · `pool_items` · `import_batches` | 568 池 / 3.2 万条目（实测）。池有 `kind` 分类，条目有 `label`(中文) + `tags`(英文) |
| **配置** | `gen_profiles` · `profile_params` · `recipes` | 预设与配方是用户的，**清库必须回迁**。`profile_params` 按 `(profile_id, workflow_id, key)` 存模型专有参数 |
| **会话** | `draw_sessions` · `draw_profiles` · `session_loras` · `session_recipes` · `session_recipe_slots` | 一次「开台」的全部输入。后两张是配方快照 |
| **抽卡结果** | `draws` · `draw_slots` · `draw_slot_tags` · `slot_extras` | 一抽一行 `draws`；逐槽 `draw_slots`；逐词 `draw_slot_tags`；意群与锁定 `slot_extras` |
| **任务与产物** | `generation_jobs` · `job_snapshots` · `images` · `image_assets` · `concepts` · `concept_images` · `event_logs` | 任务、任务快照、图片、图片与角色的关联、概念索引、结构化日志 |

关系主干：

```
pools ─< pool_items
recipes ─┐
gen_profiles ─┬─< profile_params
              └─< draw_profiles ─< session_loras
draw_sessions ─┬─< session_recipes ─< session_recipe_slots
               ├─< draw_profiles
               └─< draws ─┬─< draw_slots ─< draw_slot_tags
                          ├─< slot_extras (slot_kind='draw')
                          ├─< generation_jobs ─< job_snapshots
                          └─< images ─< image_assets
                                        └─< concept_images >─ concepts
```

**三条数据纪律**：

1. **只加表，不改表**（2026-11-16 起）。`create_all` 自动建表，老库零风险，
   不需要写 migration。要新字段就新开一张表用 `job_id` / `slot_id` 关联。
2. **不改池子文本**。条目里手写的 `(x:1.2)` 权重在**出图出口**剥（`core/weights.strip_weights`），
   明细同步剥并留 `raw_tags`。池子页永远能看见原貌。
3. **清空重建只走 `scripts/reset_db.py`**：备份 → 旧库与图片**移动**到 `data/archive/<时间戳>/`
   （不物理删，可回滚）→ 重建字典 → 按名字回迁 checkpoint / LoRA / 自建配方。

## 7. WorkflowSpec：三种模型共用一个 ComfyUI

实测 SDXL / Anima 两套节点图的 loader 不同，但**提交协议完全相同**（`/prompt` + `/history` + `/view`）。
所以抽象对象是**节点图规格**，不是「后端」：

| 模型 | 加载节点 | 输出节点 |
|---|---|---|
| SDXL | `CheckpointLoaderSimple`(1) + `LoraLoader` | `SaveImage`(7) |
| Anima | `UNETLoader`(44) + `CLIPLoader`(45) + `VAELoader`(15) + `LoraLoaderModelOnly` | `SaveImage`(46) |

规格文件与节点图同名、`.spec.json` 后缀：

| 字段 | 含义 |
|---|---|
| `id` / `label` | 稳定标识 / 界面显示名 |
| `template` | 节点图文件名 |
| `params` | 占位符 → 取值来源（`prompt` / `negative` / `seed` / `prefix` / `profile:key` / `lora_chain:slot` / `const:value`） |
| `lora` | LoRA 注入策略：`class_type`、输入/输出槽位、链起点；`null` = 该模型不支持 |
| `result_nodes` | 只从这些节点的 `outputs.images[]` 取结果（不再扫全部节点） |
| `capabilities` | `negative` / `lora` / `ref_image`，供 UI 与校验使用 |

**加一个新模型 = 加两份文件，不改主链路。**

1. ComfyUI 里搭好图，导出 API 格式存成 `backend/workflows/<id>.json`，把要注入的字段改成 `$占位符`
2. 写 `<id>.spec.json`：`params` 来源、`lora` 策略、`result_nodes`、`capabilities`
3. 有专有参数（clip/vae）就在设置页加输入，值存 `profile_params`
4. 刷新页面，`/api/config` 自动下发新 workflow 到选择器
5. 用该 workflow 提交一抽，确认出图与结果解析

不需要动：`comfy.py`、`worker.py`、`generation.py`、任何表。
没有 spec 的老 workflow 按 SDXL 兼容模式处理（`/api/config` 标 `spec: false`），老数据不炸。

### 模型文件放在哪：`checkpoints` 与 `diffusion_models` 之间的一座桥

Civitai 的底模默认下到 `ComfyUI/models/checkpoints/`，但 **`UNETLoader` 只枚举 `models/unet` 和
`models/diffusion_models`**，而 Anima / Flux 这类权重是**纯 UNet**（实测 Civitai 的 Anima int8：
1581 个张量全是 `model.diffusion_model.*`，没有 `first_stage_model`、没有文本编码器），
`CheckpointLoaderSimple` 加载它会直接报「Could not detect model type」。

所以下载目录和加载器目录之间必须建立链接：

```
python scripts/link_unet_models.py            # 幂等，可反复跑
python scripts/link_unet_models.py --dry-run  # 只看会做什么
```

- 判据按**内容**不按文件名：读 safetensors 头部（几 KB，不加载权重），有
  `model.diffusion_model.*` / `diffusion_model.*`，且不含 `first_stage_model` / `cond_stage_model` /
  `vae.` / `text_encoders.` → 纯 UNet，需要链接。所以以后下任何 diffusion model 都会被自动带过去。
- 用**硬链接**（`os.link`）：同一份字节、不占第二份空间、删掉一边另一边仍在。跨卷会明确报错而不是偷偷复制。
- `start.bat` 在**拉起 ComfyUI 之前**已经调用它，所以下载完直接双击启动即可；
  但 **ComfyUI 运行中不刷新** `/object_info` 枚举，新模型要重启 ComfyUI 才出现在下拉里。

### 蒸馏模型的参数必须成套：Anima Turbo / Base 不能混搭

Anima（Qwen-Image）是蒸馏过的模型，**步数、CFG、Turbo LoRA 三者是一个整体**，拆开就废图：

| 模式 | steps | cfg | sampler / scheduler | turbo LoRA |
|---|---|---|---|---|
| **Turbo（默认）** | 10 | **1.0** | euler / normal | `anima-turbo-lora-v0.2.safetensors` @ 1.0 |
| **Base（高画质）** | 25 | **4.5** | euler / normal | 不加载 |

混搭的后果（都实测过）：

| 组合 | 结果 |
|---|---|
| 10 步 + CFG 4.5 + 无 LoRA | **整张彩色色块汤**（latent 没收敛，CFG 再把噪声放大） |
| 10 步 + CFG 4.5 + 有 LoRA | 过曝、颜色焦糊，人物粘在一起 |
| 25 步 + CFG 1.0 | 画面发灰、没有细节（无引导等于弱化提示词） |
| 步数 / CFG 对但 LoRA 缺失 | 轮廓散、结构拼不起来 |

两条纪律：

1. **改 CFG 必须同时改步数与 LoRA**，不能只动一个。
2. Turbo LoRA 只认 CFG ≈ 1，把它和 CFG 4.5 一起用等于自我抵消。

排查判据：出图是**色块 / 噪点 / 结构糊成一团**但没报错 → 先看这一抽的 `cfg` 与 `session_loras`，
不要怀疑模型文件或 VAE。这类错误 `status` 永远是 `succeeded`，日志里什么都看不到。

另外，`draw_profiles` + `session_loras` 是**会话级快照**，换模型族时它们不会自动清空：
SDXL 的 LoRA（韶恩、neg4all_xl 之类）套在 Qwen-Image 的 UNet 上不会报错，只会静默污染画面，
换族时记得把 LoRA 一起换掉。

## 8. API

统一响应：成功 `{ok:true, data:...}`，失败 `{ok:false, error:{code, message, request_id}}`。
前端只读 `api.js`，不要在视图里裸 `fetch`。

| 域 | 端点 |
|---|---|
| system | `GET /health` `GET /ready` `GET /api/config` `GET /api/comfy/status` `GET /api/comfy/models` `GET /api/logs` |
| pools | `GET/POST /api/pools` `GET/DELETE /api/pools/batches[/{id}]` `GET /api/pools/tag-suggest` `GET /api/pools/items` `POST /api/pools/import` `GET/PUT/DELETE /api/pools/{id}` `GET/POST /api/pools/{id}/items` `PUT/DELETE /api/pools/items/{id}` `GET /api/pools/{id}/items` |

## 9. 前端分域

`app.js` 从 2397 行降到 277 行，只剩 composition root：`refreshBase()`、
事件委派（click / input / change / keydown / hover）、`startStream()`、`boot()`、视图注册、诊断句柄 `window.__gacha`。

| 层 | 模块 | 规则 |
|---|---|---|
| 内核 | `store.js` (11) | 唯一可变 state。别的模块只能读写字段，**不许再导出副本** |
| 内核 | `core/ui.js` (30) | `$` / `view` / `num` / `toast` / `fail` / `done` |
| 内核 | `core/router.js` (85) | `registerView` / `refresh(view)` / `onRoute` / `setNav` / `updateStatus` |
| 视图 | `views/*.js` | 一页一文件：渲染 + 它自己的动作。已换 Vue：jobs / gallery / pools / recipes / settings；仍原生：draw（含 assembly）、concepts |
| 领域 | `features/*.js` | 跨页面能力。**不得 import 视图的 render**，要重绘走 `refresh(view)` |
| 纯函数 | `widgets.js` / `detail.js` | 零 import。Vue 用的选项一律**返回数据**（`poolOptionGroups` / `loraOptionList`），不返回 HTML |

### 9.1 动作注册表

每个模块 `export const actions = {'data-act': async (btn) => {}}`，`app.js` 只有一个委派器：

```js
const handler = handlers[btn.dataset.act];
if (handler) await handler(btn);        // 未注册 = 静默
```

跨域动作（`view-retry`、图片评分 / 收藏）留在 `app.js`。**动作只有一份实现**，原生视图与 Vue 视图共用。

### 9.2 Vue 与原生共存的三条约定

1. 视图对外导出名不变（`renderX` / `actions` / 模块级 `refreshX()`），`app.js` 与 router 一行不用改
2. 组件外留模块级 `ref` / `reactive` 当数据入口，外部喊一声就是改数据，**不碰 DOM**
3. 按钮继续写 `data-act`；只有纯本地编辑（槽位增删移、LoRA 权重、筛选输入）才用 `v-model` / `@click`

卸载时机在 `refresh()` 的**渲染之后**，且比对「渲染前那个实例」——
设置页 `await` 拉 ComfyUI 模型列表最坏 20 秒，渲染前卸载会先白屏一片。

### 9.3 输入补全

一个浮层 + 一张 provider 表（`features/suggest.js`）。输入框只写一个属性：

```html
<input data-suggest="checkpoint">                    <!-- 替换整个值 -->
<input data-suggest="neg" data-suggest-append>       <!-- 多值：只替换最后一个逗号段 -->
```

provider 覆盖：池 / tag / 概念 / 预设 / 配方 / checkpoint / LoRA / VAE / CLIP / 负向词 / 历史目录 / 过滤表达式。
不覆盖的必须显式标记：`class="qf"`（快速筛选）、`data-filter-only`（输入即过滤）、
`data-free-text`（自由描述）、`data-secret`（令牌）。

三条硬要求：浮层挂 `body` + `position:fixed`（落点都在 `overflow:auto` 容器里，行内定位必被裁）；
用 `mousedown` 不是 `click`（click 会先触发 blur 关掉浮层）；
写回后**派发 `input` 事件**（Vue 的 v-model 只认 DOM 事件，只改 value 会「框里有值、草稿是空」）。

### 9.4 提示词汉化

`data/vocab/danbooru-cn.json` 是 `{英文 tag: 中文}` 双向映射（33071 条，`scripts/fetch_vocab.py` 可重建）。
中文输入给中文候选、英文输入给英文候选，候选双语显示，但**写进 prompt 的永远是英文 tag**。
查询词与结果分离，中文绝不进 prompt。

## 10. 五条硬约定

| # | 约定 | 违反的后果 |
|---|---|---|
| 1 | **只加表不改表** | 改表要写 migration，老库升级有风险；新开表用 id 关联即可 |
| 2 | **净化在出图出口**：`strip_weights` 在拼 prompt 时剥，池子文本一个字不改 | 就地清洗不可逆，且「卡池页看原貌」失效、概念 key 批量漂移 |
| 3 | **装配默认全关**：所有格子 fallback=off，打开哪格哪格才进 prompt | 随机到不该出的东西；改默认值必须升持久化 key（`gacha_assembly_v2`），否则旧会话状态复活 |
| 4 | **补全只有一套**：新增输入框写 `data-suggest`，不另写事件 | 42 个输入框会分裂成 42 套实现 |
| 5 | **抽象必须画成形状**：人物是纸娃娃、场景是画面，点部位进池 | 一行字看不出「发型」管的是哪儿；位置本身就是说明 |

另外两条工程纪律：

- **部分更新接口是整体覆盖语义**：`upsert_recipe` / `upsert_profile` 只传改动字段会把
  关联的预设、LoRA、workflow 清空。就地改必须带回 `gen_profile_id`、`loras`、`workflow`。
- **代码改动落盘即 commit**，中文提交信息写清三件事：改了什么、为什么改、怎么验证的。


关自动拉起：`set GACHA_COMFY_AUTO=0`；换便携版目录：`GACHA_COMFY_DIR=...`。

**三道验收闸，改完必跑**：

| 闸 | 命令 | 基线 | 守什么 |
|---|---|---|---|
| 后端冒烟 | `python scripts/smoke_test.py` | 113/113 | mock + 临时库副本，全链路契约；不污染正式库 |

- **`data-act` 契约**：全前端产出的 `data-act` ⊆ 注册表键集合，反向也查死动作

真实出图另跑 `python scripts/live_test.py`（需要 ComfyUI 在线，验冒烟测不出来的东西：

## 12. 明确的非目标

写在这里是为了以后不被「顺手加上」：

- **不做多用户 / 不做登录**。单人本地工具，JWT / RBAC 是过度设计
- **不引构建链**。没有 Vite、npm、.vue 单文件组件；`start.bat` 双击必须能跑
- **不引第二个常驻服务**。前端由后端托管，实时用 SSE；出图是本机 ComfyUI 的事
- **不把语义索引入库**。`data/semantics/` 可随时重建，数据库只存结构化事实
- **不用线上文生图 API**。慢、带水印、要 key；本机 anima 已经够快
