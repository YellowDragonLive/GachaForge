# 运维手册 · 数据迁移

> **唯一口径**：卡池数据的导入、回滚、备份全部走本文命令与 `scripts/` 固定入口。
> 数据库是唯一事实源；根目录的 JSON / CSV / TXT 只是「导入来源」，运行期不再读取。

## 2. 字段映射

| 旧概念 | 新表 / 字段 |
|---|---|
| JSON 文件 / 词卡 txt | `pools.source` + `pools.source_ref` + `import_batches.source_path` |
| JSON 自动识别的数据池 | `pools.slug`（`来源:池名` 格式）、`pools.kind`（角色/画师/风格/…） |

| `combos/*.json` | `recipes.definition_json`（`fixed_head / slots / template / fixed_tail`） |

冒烟脚本会用 `zh_TW.json` + 固定 seed 逐条比对新旧结果，确保行为未漂移。

## 3. 固定命令

```
python scripts/init_db.py                       # 建库 / 升级（Alembic）
python scripts/migrate_legacy.py --dry-run      # 只看计划，不写库
python scripts/migrate_legacy.py                # 执行导入（重复运行安全）
python scripts/migrate_legacy.py --if-empty     # 已有卡池则跳过（start.bat 用）
python scripts/migrate_legacy.py --rollback 3   # 回滚第 3 号导入批次
python scripts/backup_db.py                     # 备份
python scripts/backup_db.py --list              # 列出备份
python scripts/backup_db.py --restore <文件名>  # 恢复
```

批次 ID 可在「卡池管理 → 导入与批次」表格看到，或调 `GET /api/pools/batches`。
回滚会按 `pool_slug` 前缀删除对应卡池（外键级联删条目）并删掉批次记录；`wc:*` 对应全部词卡池。

**重复导入是安全的**：已存在同名 slug 的池会跳过，不会重复插条目。想强制重建某个池，先回滚对应批次再导入。

## 4. 新增数据源

### 单个 JSON / CSV

1. 把文件放进项目目录内（任意子目录）。
2. 「卡池管理 → 导入」填相对路径，或调 `POST /api/pools/import {"path": "xxx.json"}`。
3. 支持任意结构 JSON：扁平字典、数组、嵌套对象、空格分隔的短词列表会自动识别成池。
4. CSV 约定两列：`中文名, 英文 tag`。

### 词卡目录

把 `.txt` 词卡目录放进项目内，导入时填目录路径。每个文本文件 = 一个池，池名 = 相对路径（与 `__池名__` 模板语法一致）。
也可改 `.env` 的 `GACHA_WILDCARDS_DIR` 后重跑 `python scripts/migrate_legacy.py`。

### 历史图片目录（画师图鉴并入）

「画廊 → 并入历史画师图鉴」填项目内目录，或调 `POST /api/images/register-dir {"path": "..."}`。
只读扫描 png/jpg/jpeg/webp/gif（单目录上限 2000 张），生成缩略图到 `data/thumbs/`，**不移动、不复制原图**，记录 `images.origin="gallery"`。
已注册路径会自动跳过，可重复执行。

> 实测 `artist_style_test_20260526/` 与 `yoga_style_guide_20260527/` 两个历史目录当前不在 `X:/image`，
> 因此注册表为空属于正常状态；目录恢复后执行上面的注册即可，不阻塞系统上线。

## 5. 表结构与变更

建库与升级一律通过 Alembic：`backend/migrations/versions/0001_initial.py`。
表定义以 `backend/app/models.py` 的 ORM metadata 为唯一来源，迁移里用 `Base.metadata.create_all()` / `drop_all()`，避免手写 DDL 与模型漂移。

后续加字段的正确做法：改 `models.py` → 新增一个 revision 文件 → `python scripts/init_db.py` → `python scripts/smoke_test.py`。
不要直接改 `data/gacha.db`，不要删除该目录。

核心表：`pools`、`pool_items`、`recipes`、`gen_profiles`、`draw_sessions`、`draws`、
`generation_jobs`（含唯一 `idempotency_key`）、`images`、`import_batches`、`event_logs`。

---

## 6. 复现与导出

每次抽卡会落 `draw_sessions`（配方快照 + 参数快照 + seed + workflow 版本）和逐抽 `draws`；
每张生成图记录 `prompt / seed / comfy_prompt_id / sha256`。因此：

- 「画廊 → 同参重跑」用同一 `draw_id` 重新提交任务（`force=true`）。
- 「画廊 → 导出元数据」导出当前筛选结果的 JSON，含全部可复现字段。

---

## 7. 注意事项

- `data/`、`vendor/`、`*.db`、`*.log` 均在 `.gitignore` 中，不要提交运行时数据。
- 备份用 `scripts/backup_db.py`（SQLite backup API，自动处理 WAL），不要直接复制正在写入的 `.db` 文件。
- 旧 JSON 文件仍在根目录，仅供追溯与重新导入；新系统运行期完全不读它们，改动旧文件不会影响已导入的数据。
