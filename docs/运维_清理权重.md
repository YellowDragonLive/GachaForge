# 运维：超重权重（池子不动，出图时剥）

词卡从外面导入时常自带 SD1.5 时代的手写权重：`(long petticoat:1.2)`、`(a, b:1.3)`、
`anal beads:1.2`、`((gothic lolita, Idol costume):1.3)`。这些在抽卡里是污染 ——
一个条目只是「一个概念」，强调程度该由抽卡时的人决定，不该由词卡写死 1.2/1.5。

**标准口径：只在「写进 prompt 的那一刻」剥，池子里的原文一个字都不改。**

```text
pool_items（原始导入文本，卡池页/选择器看到的就是它）
      │  抽卡
      ▼
run_recipe() / build_prompt()   ← strip_weights() 在这里剥
      │
      ▼
正向 prompt（干净，无 :1.2）
```

为什么不在库里改：

1. **不可逆**。改完想找回原词卡只能靠备份，而备份不是每个人都记得留。
2. **卡池页要能看见原貌**。用户判断「这条为什么带 1.2」需要看原文；写死清理后，
   再问「是不是我导入错了」就无从对证。
3. **概念索引的 key 来自 tag 文本**，写库会让 531 个 key 一次性漂移，历史出图对不上。
4. **重新导出/同步会把清理结果带出去**，污染回源头。

落点（两个 prompt 出口，都覆盖）：

- `backend/app/core/recipes.py::run_recipe` —— 配方抽卡（含装配面板锁定、模板 `__池名__`、
  `fixed_head` / `count_tags` / `fixed_tail`）。明细里会留 `stripped_weight: true` 和
  `raw_tags`（原文），方便对照「这条少了 `:1.2` 是清理，不是抽错」。
- `backend/app/core/pools.py::build_prompt` —— 手工卡片直接拼的那条路。

## 审计（默认只读，不写库）

```bat
python scripts/clean_weights.py                            :: 命中数 + 按池分布 + 样例，绝不写库
python scripts/clean_weights.py --limit 20                 :: 多看几条样例
python scripts/clean_weights.py --prompt "(a:1.2), b"      :: 预览一段文本清完长什么样
python scripts/clean_weights.py --self-test                :: 只跑内置用例，确认规则没被改坏
```

导入新词卡后跑一次审计，看命中数是否合理；**不需要也不要写库**，出图时自动干净。

## 规则（实现见 `backend/app/core/weights.py`）

| 输入 | 输出 | 说明 |
| --- | --- | --- |
| `(standing:1.2)` | `standing` | 连括号一起删：留着 `(standing)` 仍是 1.1 倍强调 = 没清干净 |
| `(bottomless, lying:2)` | `bottomless, lying` | 整组权重 |
| `((gothic lolita, Idol costume):1.3)` | `(gothic lolita, Idol costume)` | 双括号：删外层权重，内层是原本的强调，保留 |
| `(a (b:1.2):1.3)` | `a b` | 嵌套由内向外剥 |
| `anal beads:1.2` | `anal beads` | 裸权重（整段以 `:数字` 结尾） |
| `ribbons:1.2)` （丢了开括号的坏数据） | `ribbons` | 孤立权重兜底，顺带删多余的后括号 |
| `<lora:name:0.7>` / `<lyco:...>` | 原样 | 尖括号整段跳过，里面是 LoRA 权重 |
| `reverse:1999` / `(重返未來:1999)` | 原样 | 权重区间默认 1.1~5.0，年份冒号不会被误吃 |
| `(bloom:0.5)` | 原样 | 降权不在清理范围（只清超重） |
| `((full body))` | 原样 | 没有 `:数字` 的括号强调不算权重，脚本不猜 |

没有超重权重的文本**一个字都不改**（不顺手把 `1girl,1boy` 补成 `1girl, 1boy`）。

## 只有确实要净库时才用 `--apply`

场景很窄：把库整份导给别的工具、或要让卡池页本身也看不到权重。它会**改写
`pool_items.label/tags`**，不可逆，务必先看审计清单。

```bat
python scripts/clean_weights.py --apply                  :: 真的写库（改池子文本）
python scripts/clean_weights.py --apply --keep-brackets  :: 只删权重，保留 ()
python scripts/clean_weights.py --restore data/backups/gacha-weight-<时间戳>.db   :: 回滚
```

安全口径：

- 默认只读，`--apply`（旧别名 `--yes`）才写；写库前用 SQLite backup API 备份到
  `data/backups/gacha-weight-<时间戳>.db`（WAL 未落盘也能拿到一致快照）。
- 单事务提交，失败整体回滚；`content_hash` 同步重算（label+tags 的导入去重指纹）。
- 幂等：清完再跑一遍命中数为 0；脚本结尾自复查并打印「复查残留」。
- `--restore` 按 id 逐行比对，只把真被改过的行写回；恢复前先把当前库备份成
  `gacha-before-restore-<时间戳>.db`。只碰 `pool_items` 的 label/tags/content_hash。
- 括号不配对的（`(a:1.2` 缺后括号）只清能清的，脚本会点名列出，剩下的不猜。
