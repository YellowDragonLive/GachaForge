# 运维手册 · 启动与验收

> **唯一口径**：本文件是启动、验收、排障的唯一依据。不要现场拼命令。
> 适用：`X:/image` 抽卡工作台 v1.0（FastAPI + SQLite + 原生前端）。

---

## 1. 启动（唯一入口）

双击项目根目录的 **`start.bat`**，或在终端执行：

```
X:\image> start.bat
```

它会自动完成：**生成 .env（首次）→ 自动挑选已装好依赖的 Python → 从本机已有环境搬入离线 AI 依赖（首次，绝不联网）→ 检测 ComfyUI → 建库（v2 关系基线）→ 导入旧数据（仅库空时）→ 离线构建画师语义索引（首次，失败只告警）→ 启动服务 → 打开浏览器**。

> 当前基线是 `0001_v2_relational`（方案 C 彻底规范化）。**旧的 `0001_initial` 库不能直接升级**：若手上还有 v1 库，先按第 2 节「清空重建」跑 `reset_db.py`，旧库会归档而不是删除。

> **零下载约定**：语义抽卡用的 `onnxruntime` / `tokenizers` 和 87MB MiniLM ONNX 权重，本机早就有了，一律**直接搬进项目**（`vendor/pydeps/`、`data/models/minilm/`），不 `pip install`、不联网、不要 API key。所有候选 Python 都没有核心依赖时，`start.bat` 只打印手动安装提示并停止，**不会自动下载**；ONNX 依赖缺失时语义面板降级，抽卡主流程不受影响。

### 为什么启动脚本要挑 Python（双击时的坑）

**双击 bat 时 `python` 来自系统 PATH，是 `X:\ProgramData\miniconda3\python.exe`（3.13.13），里面只有 httpx，没有 fastapi / uvicorn / SQLAlchemy / Pillow**；核心依赖实际装在 WorkBuddy 自带的 Python（3.13.14）里。以前 `start.bat` 靠自动 `pip install` 把这事掩盖了，去掉自动安装后双击就会报 `No Python with the core dependencies was found`。

现在 `start.bat` 按顺序探测并**全程用同一个解释器**（启动时会打印 `[start] Python: ...`）：

| 顺序 | 候选 |
|---|---|
| 1 | `GACHA_PYTHON` 环境变量显式指定（优先级最高，排障时可强制指定） |
| 2 | 项目内 `.venv\Scripts\python.exe` |
| 3 | PATH 里的 `python`（在 WorkBuddy 终端里启动时通常命中这个） |
| 4 | `%USERPROFILE%\.workbuddy\binaries\python\versions\*\python.exe`（本机依赖所在的解释器） |

判据统一是能否 `import fastapi,uvicorn,sqlalchemy,alembic,httpx,websockets,PIL`。四个候选都失败才提示手动装一次，**绝不联网**。

实际逻辑在 `scripts/start.bat`，服务由 `scripts/run_server.py` 拉起；地址与端口统一读 `.env`，默认 `http://127.0.0.1:8765/`。
按 `Ctrl+C` 停止服务。

### ComfyUI 在线检测

`start.bat` 会探测 `.env` 里的 `GACHA_COMFY_URL`：

| 情况 | 行为 |
|---|---|
| ComfyUI 在线 | 真实出图模式 |
| ComfyUI 离线 | **自动切到 mock 模式**（设 `GACHA_COMFY_MOCK=1`），生图返回占位图，抽卡/任务/画廊全链路照常可用 |

想强制固定模式，直接改 `.env` 的 `GACHA_COMFY_MOCK`；注意 `start.bat` 设置的环境变量优先级高于 `.env`，手动命令行启动时以环境变量为准。

> 旧的 `start.bat`（画师图鉴 3000 端口）和 `gacha_start.bat`（旧抽卡器 8765 端口）已分别改名为
> `start_legacy_gallery.bat` / `start_legacy_gacha.bat`，内容一字未改。**不要同时启动旧抽卡器和新服务**，两者默认都占 8765。

### v2 关系模型与概念缩略图（两者互不影响）

- **单一事实源**：抽卡明细在 `draw_slots / draw_slot_tags`，参数快照在 `draw_profiles / session_loras / session_recipes`，图片元数据在 `image_assets`，概念索引在 `concepts / concept_images`。主表不再存 `detail_json / meta_json / *_snapshot_json`，Alembic 基线为 `0001_v2_relational`。对外 API 响应形状与 v1 一致，结果区与复现逻辑不用改。
- **概念墙按需悬浮**：列表接口只返回文字与计数，**不铺任何 `<img>`**；hover / 键盘 focus 才请求 `/api/concepts/cover?key=` 浮出**一张**代表图，前端按 key 缓存、新图产出后整体失效。点概念名进 `#/concept/<key>` 详情页，首屏最多 50 张历史图，可评分 / 收藏 / 继续加载；评分收藏变化会重算封面（`rating×2 + favorite×5 + 新鲜度`）。
- 概念粒度来自**结构化槽位 tag**，不是整段 prompt 切词；池类别仍直读 `pools.kind`。索引在出图落库时增量维护，`python scripts/rebuild_concepts.py` 可全量重建。
- **语义检索「想要的感觉」**是可选增强，索引由 `scripts/build_semantics.py` 离线预计算。所需两样本机现成：`scripts/vendor_deps.py` 把「艺术家智能选择」`.venv` 里的 `onnxruntime 1.27.0` / `tokenizers 0.23.1` 搬进 `vendor/pydeps/`；`embed.prepare_model()` 把 Chroma 缓存里已解压的 all-MiniLM-L6-v2 权重**剪切**进 `data/models/minilm/`（不复制两份，缓存 `onnx.tar.gz` 仍可恢复）。两者都零联网、零 pip。
- 产物 `data/semantics/` 与模型 `data/models/` 均不进 git、可随时重建。运行时只做 numpy 余弦，不加载 chromadb、不新增常驻服务。
- 索引缺失或依赖没搬好时，`start.bat` 只打印一行 WARN，语义面板显示降级提示，**抽卡、概念墙、画廊、任务全部照常可用**。补依赖跑 `python scripts/vendor_deps.py`，补索引跑 `python scripts/build_semantics.py`。
- 画师风格锚点样图通过 `/api/semantics/thumb?index=N` 只读分发，路径白名单由构建时的 `thumbs_dir` 决定，不接受客户端传路径；不复制 3.2GB 原图。

### 清洗运行数据（开发期每轮测试前）

`clean_db.py` 是「测试跑脏了」的固定入口，**默认 dry-run，加 `--yes` 才写**：
先备份整库到 `data/archive/clean-<时间戳>/gacha.db`，再把 `data/outputs/`、`data/thumbs/`
下的图片**移动**（不删）到同一归档目录，最后在一个事务里清空 14 张运行表并 VACUUM。
字典（568 池 / 32490 词条）、配方、参数预设、导入批次一律不动，库回到刚导入完的样子。

**执行前先停服务**（8765），否则 `vacuum` 可能被锁、且清理途中服务可能继续写。
脚本自带指错库保护：`pools`/`pool_items` 不存在或词条为空会直接拒绝。
回滚：把归档目录下的 `gacha.db` 与 `data/outputs/`、`data/thumbs/` 按相对路径搬回原处。

与 `reset_db.py` 的分工：`clean_db` 只清跑出来的数据（几秒）；`reset_db` 是换库/换模型后
的重建（几十秒 + 回迁配置），只在架构变更时用。刚清洗完概念墙为空是正常的，抽卡生图后自然长回来。

### 意群双语词表（提示词汉化）

抽卡台每个意群（场景 / 人物 1 / 人物 2 …）底部各有一个自由词输入框，中英文都能查：
输入「黑发」出中文候选、输入 `silver h` 出英文候选，候选一律显示「主语言 · 对照语言」双语，
点一下把**英文 tag** 写进那个意群。词表本质是 `{英文tag: 中文}` 的 map，不是在线翻译。

- 数据源：`Aleiluo/comfyui-danbooru-translate-cn` 的 `danbooru-cn.json`（MIT，33071 条），
  `scripts/fetch_vocab.py` 下载到 `data/vocab/`（不进 git、可重建）。
- **下载通道**：本机走内网代理，`raw.githubusercontent.com` / `cdn.jsdelivr.net` 握手失败；
  脚本实测可用的通道是 `ghproxy.net` 前缀，且下载后做 JSON + 条目数校验，
  绝不能把代理错误页存成词表（那样补全会静默全空）。改通道只改脚本的 `SOURCES`。
- 后端 `core/vocab.py` 懒加载 + mtime/size 签名缓存；缺词表时 `/api/vocab/*` 返回 503，
  不影响抽卡出图（和语义索引同一套降级约定）。
- 覆盖：对本项目 26940 个唯一 tag 精确命中约 33%，其余多是角色/画师专名（通用表没有），
  用候选查不到时回车可原样写一个英文 tag（逃生口），中文不写进 prompt。

### 清空重建（方案 C 的固定流程）

`reset_db.py` 是唯一口径，**先 `--dry-run` 看清单再执行**：

1. 备份 `data/gacha.db` 到 `data/backups/gacha_<时间戳>.db`；
2. 旧库（含 `-wal` / `-shm`）与全部原图 / 缩略图**移动**到 `data/archive/<时间戳>/`，保持原相对路径，**不物理删除**；
3. `init_db.py` 用 v2 基线建空库 → `migrate_legacy.py --if-empty` 重建 568 池 / 32490 词条 / 内置配方；
4. 把归档库里的**参数预设（含真实 checkpoint / LoRA）与自建配方按名字回迁**，新库运行数据保持 0。

回滚：把 `data/archive/<时间戳>/` 里的 `gacha.db` 与 `data/outputs/`、`data/thumbs/` 文件移回原路径。**旧归档库只读，不提供从 `0001_initial` 升级到 v2 的路径**。清空后概念墙为空是正常的，抽卡生图后自然长回来。

冒烟脚本默认强制 mock，**不需要 ComfyUI 在线**，覆盖 76 项检查（算法一致性、复现、两种抽卡模式的 detail 契约、按池过滤语义与告警、表单过滤覆盖槽位级 filter、大小写不敏感、`/api/pools/tag-suggest` 点选数据源、**无对应槽位的点选条件自动补入 prompt / 已有槽位不重复补 / 抽卡台左右布局接线**、**结果卡内联状态接口 `/api/draws/status`（批量返回最新任务与已出图、非法 id 容错）**、**v2 关系表单事实源 / 概念列表零图片 / 按需单张封面 / 详情页 50 张上限 / 语义卡片不叠图 / 索引缺失时 503 降级**、**离线依赖零下载约定 / vendor 依赖已搬入 / 模型权重已剪切进项目 / start.bat 自动挑选解释器 / 清库脚本与 v2 基线**、Node 前端纯函数契约（含线稿小人「物品→部位」映射 / 场景画框三区 / 部位与池的匹配排序 / 池 chip 行 / 状态栏立绘 key 推导 / 人数 tag 剥离 / 任务卡锁定标记）、幂等、任务状态机、图片、静态页、错误结构）。其中前端契约由 `scripts/test_frontend.mjs` 提供，本机无 node 时自动跳过该项。

**隔离保证**：冒烟全程跑在 `%TEMP%/gacha_smoke_*` 的临时库副本上——副本只复用卡池 / 配方 / 预设，运行时表（含 v2 的槽位、快照、资产、概念表）一律清空；生成图也写临时目录，结束后释放连接并删除。所以**跑冒烟不会写正式库、不会污染画廊**，正式库记录数前后应完全一致。正式库尚不存在时，脚本会在临时库自行建表并导入旧数据。

## 3. 验收清单

### 自动（每次改动后跑）

```
python scripts/smoke_test.py
```

必须输出 `== 汇总: 76/76 通过 ==`（无 node 环境仍应是 76/76，该项标注「跳过」）。任何 FAIL 都不要交付。
单独看前端契约可跑 `node scripts/test_frontend.mjs`，应输出 `== 前端 detail 契约: 47/47 通过 ==`（含：「线稿小人：部位槽位对齐身体 / 三态写在身上 / 空状态不可点」、「场景线稿：画面=背景、色点=画风、画框=构图」、「部位版面：格子与身体位置的对应关系写在 CSS 里」、「池匹配：点哪个部位就先摆哪些池」、「池 chip：全部在最前，选中池即使排在后面也提到行首高亮」、「池选择接线」）。

**改完 UI 要眼见为实**（契约测试只能断言字符串，看不见「小人画歪 / 格子被裁 / 悬停没生效」）：

```bash
node scripts/ui_shot.mjs                        # 抽卡台首屏：整页 + 左栏
node scripts/ui_shot.mjs --steps steps.json     # 按步骤点选并逐屏截图（默认存 temp/ui-shots）
```

`steps.json` 是一个数组：`[{"name":"03-locked","js":"document.querySelector('.asm-entry').click()","wait":1800,"sel":".draw-side"}]`，`sel` 省略 = 整页。脚本用无头 Chrome + CDP，零依赖，端口 9222 没被占用时会自己起浏览器、跑完自己收掉；页面有 JS 异常会以退出码 1 结束。它会**强制 reload 并清 sessionStorage**（否则拍到旧 CSS、或带着上一轮的卡片），要保留状态加 `--keep-state`。
若怀疑隔离失效，比对冒烟前后正式库 `draw_sessions` / `draws` / `generation_jobs` / `images` 的行数，应完全不变。

### 手工（首次上线 / 换机器后）

1. 双击 `start.bat`，浏览器自动打开，顶部状态灯显示「ComfyUI 在线」或「mock 模式（占位图）」。抽卡台是**左右分栏**：左栏是**人物状态栏**（sticky 常驻），右栏是**任务卡**（一抽一张）。这个排布的目的就是**左看状态、右看图**，不用来回滚。窄屏（≤1080px）自动回落为单列。
2. **人物状态栏（抽卡台左栏的主体）**：顶部两个页签——**场景** 与 **人物 · N**。
   - **人数不是开关，是人物卡的张数**：1 张 = 单人、2 张 = 两人、全部移除 = 纯场景（prompt 写 `no humans`）。这样永远不会出现「选了多人但只有一套配置」的矛盾。
   - **每张人物卡 = 一张纸娃娃（paperdoll）**：顶部一条「角色」铭牌，中间是**虚线小人**（头 / 裙身 / 双臂带手 / 双腿 / 地面线），左右两列是把「物品(prompt)」贴到身体上的格子——左列 **发型 / 衣着**，右列 **表情 / 装备**，脚下一条 **动作**。位置就是对位关系：发型贴着头、衣着贴着身体、装备贴着手臂、动作贴着腿。**点身上那块 = 点那一格**，弹出的选择器标题会写明是哪一格。
   - **三态直接画在身上**：**虚线（灰）= 随机**、**实线 + 蓝底 = 已锁定**、**只剩底稿（不另画线）= 关闭**。都关掉时仍留一具完整的虚线身体（`.doll-body` 底稿），不会变成一坨虚线。指到格子，身上对应那块变蓝；指到身上，对应格子描蓝（纯 CSS `:has()`，不加事件不重绘）。
   - **立绘铺在小人底下当底图**：立绘来自**该角色的概念封面**（数据库里它出过的图），有图时虚线轮廓叠在照片上，照样能看出哪块是什么；点空白/照片进 `#/concept/<key>` 看这个角色出过的全部图（首屏 50 张），没锁角色时点它是去锁角色。这样「左看状态、右看图」还是能对照「像不像这个人」。
   - **立绘从哪来**：条目的 `label` 是中文（「艾比蓋兒·威廉斯 (旅行服)」），概念 key 却是英文 tag，所以立绘走条目的 `tags`（剥掉 `1girl` 这类人数 tag 后的第一个）。**从没出过图的新角色没有立绘**，只有虚线小人，出一张之后自动长出来（生图成功会重置立绘缓存）。
   - **每格三态**，靠状态灯与底色区分：**灰点 = 随机**（每抽重摇）、**蓝点 + 蓝底 = 已锁定**（每抽都不变）、**空心点 = 关闭**（这格不参与）。点格子或点身上对应部位展开条目选择器。选择器顶部可一键切回「随机」或「关闭」。
   - **选择器里的池是按部位匹配的，不是把 106 个池摊平**：标题右侧写「N 池匹配」，下面一行是可点的池 chip（`全部 3013` + 匹配度最高的 8 个，各带条目数，横向滑动看更多），再下面是完整池下拉（兜底）。**打开时默认落在匹配度最高的池**，点「衣着」直接就是能穿的衣服，不用先自己找池。
     - 匹配规则在 `frontend/widgets.js` 的 `rankPools` / `poolScore`：每个部位配两级关键词（`strong` 是正主、`weak` 是沾边），命中抬分；`sex_ / audio_ / food_ / flower_ / nudity_` 这类池即使命中关键词也压到后面（`POOL_OFF_TOPIC`）；人工整理过的母语池（`人物-` / `组合预设/` / `构图-`）微加分；条目数只做 log 微调，最多 28 分。**自己禁用的池不参与推荐**（`enabled === false` 直接过滤）。
     - 效果举例：衣着 → `组合预设/服装-女性简单穿搭` 优先；发型 → `人物-头发`；画风 → `SDXL/movements` 而不是混在「风格」里的 12 个乐器池；角色 → `wai_characters` 而不是「人物-类型」；装备 → `物品`（69 个物品池几乎全是食物和花，通用池排第一）。
   - **「全部」是多池混排，不是「按导入顺序前 60 条」**：后端 `list_items` 在没指定池时用窗口函数**每池取 3 条**再按池大小排序（`cap // 20`，至少 2 条），所以 60 条能盖住 20 个池；前端按匹配度把组排好序并渲染**可点的组头**（`组合预设/服装-女性简单穿搭`、`人物-衣服`…），点组头 = 只看这一池。搜索同样是每池取样，跨池搜。
   - **已选定单池时条目行不再重复写池名**，宽度让给条目名（`Striped top, high-waisted jeans, loafers` 能完整显示）。
   - **场景页签也是一张线稿**：一块虚线画框，**点画面 = 背景**（地平线 / 山 / 太阳是装饰）、**点右下三枚色点 = 画风**、**点画框本身 = 构图**（含三分线）。画风对所有人统一生效；场景全关 = 白底纯人物。
   - **0 张人物卡也要有个虚线小人**：空状态摆一具不可点的占位小人 + 「＋ 添加人物」，一眼看出这里本该站个人。
   - **人物六格**默认只有角色、发型、衣着随机，表情 / 装备 / 动作默认关闭——物品类下 69 个池混着食物厨具（`sausage`、`oven mitts`），默认随机只会拉低出图质量，要装备就点开搜 `sword` / `hat` / `glasses`。
   - **人物卡可复制 / 移除 / 单独设性别**。锁角色时会按条目 `tags` 里的 `1girl` / `1boy` 自动校正该人物的性别，避免「1girl + 男角色」的 prompt 冲突。多人同框的人数标签由张数与性别推导（2 女 → `2girls`、1 女 1 男 → `1girl, 1boy`、3 人以上追加 `multiple girls`）。
   - **条目的 `1girl` / `1boy` 会被剥掉**：角色条目自带人数，多人时会拼成 `1girl, 1girl`，模型只画一个人。所以抽到时一律剥离，改由面板在 prompt 开头统一写一次人数。这是「多人同框」以前做不到的根因。
   - **装配有内容时优先走装配**，此时配方与全局过滤都不参与（两者同时生效会互相筛空，最难排查）。原来的配方 / 过滤 / 看图选概念 / 一句话找画师都保留在左栏底部 **「改用配方抽卡」** 折叠区里，展开即可用。
   - 装配状态存 `sessionStorage`：切视图、按 F5 刷新都还在。
3. **抽卡台原配方路径**：展开「改用配方抽卡」→ 选「角色 × 风格 × 背景」，连抽 3、种子 42 → 点 **「抽卡并生图」**，抽卡与生图一步完成；想先审 prompt 就点旁边的「只抽卡」。再抽一次种子 42，prompt 必须逐字相同。**再切到「（不用配方 · 全池随机）」抽一次**，卡片应正常显示、明细折叠为 20 条 + 「另有 N 个槽位」，不得出现 `x.tags.join is not a function`。抽完卡配方 / 连抽数 / 种子 / 过滤等选择应保持不变；切到别的视图再回来、以及按 F5 刷新，表单、上一批结果与每张卡的任务状态都应恢复。
   - **过滤现在是点选的，不用打字**：「作用池」下拉默认「角色」（类别优先，可切到具体池或「全部卡池」）→ 点下方「热门 tag」 chip、或从 tag 下拉选一个（**选中即添加**），自动生成 `角色:asuna` 并显示成可 × 删除的条件 chip。找别的 tag 可在搜索框输入 2 个字联想。作用池选「全部卡池」会生成裸关键字，界面标黄提示全局过滤风险。想直接写表达式就展开「高级」。
   - **过滤语义**：`角色:fate` 只筛角色池，其余槽位照常抽；裸 `fate` 是**全局关键字**，会筛掉所有不含 fate 的池并让画师 / action 槽位变空，此时结果区会显示黄色告警、卡片上出现「⚠ 无匹配条目」。大小写不敏感（`角色:FATE` 等价）。
   - **优先级**：表单填了过滤就**临时覆盖**配方槽位里的 `filter`（会话级设置优先），结果区会给一条覆盖告警；表单留空才按槽位 `filter` 抽。所以想临时改成 `角色:asuna` 直接点选即可，不必改配方；想固定下来再改槽位的 tag 过滤。
   - **点选条件缺槽位会自动补，也能一键固定**：过滤原本只筛池、不新增槽位，所以配方里没有画师槽位时点 `画师:bowalia` 会被静默忽略（画师池筛过了，prompt 里却一个画师 tag 都没有）。现在抽卡时会**自动补 1 个该池的槽位**把 tag 写进 prompt，过滤区提前给出「没有对应槽位」提示，结果区再给一条「已自动补入」告警。配方已有对应槽位时不重复补。补的是本次执行副本并写进会话快照，同 seed 复现一致。想长期固定，直接点提示旁的 **「把缺的槽位加进配方」**（就地 PUT 配方，不用跳配方编辑器再手动选一遍池）；加完提示会消失，之后不带过滤抽也会带上这个 tag。
4. **任务卡（右栏一抽一张）**：卡头是编号徽标 + `第 N 抽 · seed` + **状态徽标**（待生成 / 排队中 / 生成中 x% / 已完成 / 失败），点「抽卡并生图」后**不跳页**，依次 `排队中 → 生成中 x%（条纹进度条滚动）→ 图直接长在卡片上`；失败时卡片内显示原因与「重试」，可收藏 / 重跑 / 点图开原图。卡头徽标、卡片顶部渐变条、编号都会被同一状态驱动（进行中蓝、完成绿、失败红）。下半「本抽装配」列出本次各槽位抽到什么，**锁定的槽位带「锁」标记并高亮**——这是和右栏那一眼图逐项核对的地方；上方 prompt 收进折叠区，编辑只影响复制，生图始终用抽卡快照。「任务队列」页仍保留，用于看历史与排障，但不再是必经路径。
5. **画廊**：能看到生成图缩略图，点开灯箱可看原图，收藏/评分可保存，「同参重跑」能再产生一个任务。
6. **卡池管理**：568 池可见；搜索、启停、条目预览可用；导入与批次回滚可用。
7. **配方编辑器**：新建/编辑/预览/删除均生效。槽位是**可视化表格**（池下拉 / 条数 / 权重 / tag 过滤 + ↑↓ + 移除），不用手写 JSON；模板可从下拉一键插入 `__池名__`；要粘贴旧配方就展开「高级」编辑 JSON 再点「读取下方 JSON」。
8. **双标签页**：两个标签都打开任务队列，提交一次生图，两边进度应同步（SSE）。
9. **参数预设**：抽卡台左栏预设下拉旁的 **「调参」** 就地展开抽屉，可改 checkpoint / 步数 / CFG / 宽高 / 采样器 / 调度器 / 负向词，点「保存并应用」后当前表单直接指向该预设，下一批抽卡即用新参数（LoRA 与 workflow 会原样带回，不会被清空）。LoRA 列表太长，仍在「设置」里调：**选文件 + 权重 + 添加**的行式编辑（可 ↑↓ 调顺序、移除），不需要手写 `[{"name":...}]` JSON。设置页仍保留全量配置与 ComfyUI 模型枚举，供首次配置与排障使用。
10. **看图选概念（抽卡台左栏，过滤面板的第二个 tab）**：
   - 「一句话找画师」tab：点预设 chip 或输入一句中文（如「厚涂暗色调逆光」）→ 返回画师候选卡；卡片**默认只有文字**，hover 才浮出**一张**外部风格锚点，点一下写入 `画师:xxx` 过滤。
   - 「看图选概念」tab：默认零图片的文字卡片，按类别轮转（角色 / 动作 / 服装 / 背景 / 风格 / 画师 …），单列限高可滚。**hover / focus 才按需浮出一张代表图**，点概念名进 `#/concept/<key>` 详情页看最多 50 张历史图，可点开原图、五星评分、收藏、继续加载。结果卡里的槽位 chip 同样走 hover 浮层。
   - 点卡片主体 = 把 `pool:tag` 加进过滤（池类别直接来自 `pools.kind`）；点概念名 = 进详情页，两者互不干扰。已选概念卡片会高亮。**三种 tab 选的东西都落到同一条过滤表达式上，主按钮就在同一栏下方。**
   - **语义索引没建时**：「一句话找画师」显示一行降级提示，概念墙照常可用——这是判断「数据库主源」是否生效的最快方法。**刚清空重建后概念墙为空是正常的**，抽卡并生图后自动长回来。

### 真实出图验收（需本机 ComfyUI）

1. 启动 ComfyUI（`run_nvidia_gpu.bat`），确认 `http://127.0.0.1:8188/system_stats` 可访问。
2. 重新双击 `start.bat`（探测到 ComfyUI 在线即自动进真实模式）；若之前手动把 `.env` 的 `GACHA_COMFY_MOCK` 设成过 `1`，改回 `0`。
3. 进「设置」→ 从 `/object_info` 拉到的 checkpoint 下拉里选一个真实权重并保存预设。
4. 抽 1 张：点「抽卡并生图」→ 卡片状态从排队走到生成中 → **图直接出现在这张卡上**（不必去任务队列或画廊）→ 画廊里也能看到真实图片、可五星评分。
5. 若失败，卡片内会显示 `error_message` 并可「重试」；也可去任务队列页看历史与错误详情，常见原因见 §5。

后端用的 `backend/workflows/sdxl_minimal.json` **只用 ComfyUI 内置节点**
（CheckpointLoaderSimple / LoraLoader / CLIPTextEncode / EmptyLatentImage / KSampler / VAEDecode / SaveImage），
不依赖任何自定义节点插件；旧 skill 的 `resources/workflow.json` 未被复用。

## 5. 故障排查

| 现象 | 原因 / 处理 |
|---|---|
| 打开页面显示「无法连接服务」 | `start.bat` 窗口被关了；重新双击，或看窗口里的错误 |
| `start.bat` 一闪而过 / 报 `... was unexpected at this time.` | cmd 把 `if (...)` 复合块内 echo 文案里的右括号当成块结束。现有脚本已修；**自行改批处理时不要在复合块内写圆括号** |
| 提交生图提示「ComfyUI 未运行」 | 当前是真实模式但 ComfyUI 离线：启动 ComfyUI，或重启 `start.bat` 让它自动切 mock |
| 任务反复失败后进 `dead` | 看任务卡片里的错误信息 + `/api/logs`；多为 checkpoint 名不存在、节点类型不支持、显存不足 |
| 页面顶部显示「mock 模式（占位图）」 | 正常（离线保护），不是故障；要真实出图见 §3 |
| 抽卡报「没有可用的卡池」 | 数据库为空：跑 `python scripts/migrate_legacy.py` |
| 端口被占用 | 旧 `start_legacy_gacha.bat` 或别的程序占了 8765；改 `.env` 的 `GACHA_PORT` |
| 中文/路径异常 | 路径配置建议用相对项目根目录的写法；数据目录允许放项目外，但图片接口只放行**项目根 + 配置的输出/缩略图目录**；注册历史图鉴目录仍要求位于项目内 |
| 本机设了 `HTTP_PROXY` 时接口偶发 404 | 代理会用 absolute-form 请求行转发（`GET http://host/path`）。后端已加归一化兼容；若仍异常，在环境变量里加 `NO_PROXY=127.0.0.1,localhost` |
| 图片不显示 | 先访问 `/api/images/{id}/file` 定位是记录还是文件问题；再检查 `data/outputs/` 是否被清理、文件是否落在上面三个白名单目录内 |
| 画廊缩略图/原图 404 但文件确实存在 | 文件路径不在白名单内：把它所在的目录写进 `.env` 的 `GACHA_OUTPUTS_DIR` / `GACHA_THUMBS_DIR` 后重启 |
| 冒烟跑完正式库多了测试图 | 不该发生（冒烟跑 `%TEMP%` 临时副本）。若出现，检查是否有别的进程直连 `data/gacha.db` |
| 真实模式下提交即失败 / 报 checkpoint 不存在 | 默认预设的 `checkpoint` 是空字符串（不同机器模型名不同，不能硬编码）。进「设置」从 `/object_info` 的真实枚举里选一个权重并保存预设；换机器或重建库后需重选 |
| 重启后仍是 mock 模式 | `start.bat` 只在启动时探测一次 ComfyUI；先启动 8188 再重启 `start.bat`。代理环境下探测也需能访问 `/system_stats` |
| 页面显示「页面加载失败：x.tags.join is not a function」 | 旧版前端把抽卡明细的 `tags` 一律当数组。已修：后端统一返回 `{slot, tags: list[str]}`，前端 `detail.js` 兼容历史字符串形状与脏数据。**改完代码后按 Ctrl+F5 强制刷新**，避免浏览器缓存旧 `app.js` |
| 抽完卡表单选择被重置 / 切视图或刷新后结果消失 | 旧版 `drawForm()` 把表单 value 写死为默认值，且结果只存在内存。已修：`state.form` 实时同步输入，`sessionStorage` 记住最后一次会话并在启动时只读回显。想彻底清空用「清空结果」按钮 |
| 抽卡结果卡片特别长、页面卡顿 | 「不用配方」会命中数百个卡池，明细 chip 默认最多显示 20 条并折叠；完整 prompt 一直在上方文本框里，可直接复制 |
| 配方里的 action / 画师槽位抽几次后「不见了」 | 表单「按池过滤」填了裸关键字（如 `fate`），它是**全局**过滤，会把所有不含该词的卡池整个移除。改成 `角色:fate` 或留空（用配方槽位自己的 `filter`）；现在结果区会有黄色告警、卡片有「⚠ 无匹配条目」标记，不再静默消失 |
| 照示例填 `角色:Fate` 报「过滤后没有任何可用条目」 | 旧版过滤大小写敏感，条目里多为小写 `fate`。已改为大小写不敏感，`Fate` / `FATE` / `fate` 等价 |
| 填 `角色:asuna` 却抽不到 asuna / 角色槽位空 | 配方槽位 JSON 里还写着 `"filter": "fate"`，旧版两层过滤做 AND，asuna 条目全被 fate 条件筛掉。现改为**表单过滤优先**、临时覆盖槽位 filter 并给出告警；也可把槽位里的 `filter` 清空或改成 `asuna`、表单留空 |
| 过滤区的热门 tag / tag 下拉是空的 | 数据源是 `GET /api/pools/tag-suggest`（词频词典按 `pool_items` 行数+max(id) 自动重建）。先确认卡池已导入；若 422，说明有人把该路由挪到了 `/{pool_id}` 后面，被 int 校验吞掉 |
| LoRA 下拉没有文件 | 枚举来自 ComfyUI `/object_info` 的 `LoraLoader.lora_name`。mock 模式固定返回空列表；真实模式下确认 LoRA 已放进 ComfyUI 的 `models/loras/` 并重启 ComfyUI，再点设置页「刷新状态」 |
| 点选生成的过滤条件抽不到东西 | 先看结果区黄色告警与卡片的「⚠ 无匹配条目」；作用池默认「角色」，若 tag 属于画师 / 动作池，把作用池切到对应类别或「全部卡池」（后者是全局过滤）。也可在「高级」里查看生成的表达式 |
| 新界面没出现 / 控件还是老样子 | 前端新增了 `widgets.js` 且改动了 `app.js` / `styles.css`，浏览器会缓存；**按 Ctrl+F5 强制刷新**，并确认 `/widgets.js` 返回 200 |
| 「想要的感觉」提示语义索引未就绪 | 先跑 `python scripts/vendor_deps.py` 从本机搬依赖，再跑 `python scripts/build_semantics.py` 重建索引；**都不联网**。**下方概念墙不受影响，不必为此停服务** |
| 双击报 `No Python with the core dependencies was found` | 双击时 PATH 的 `python` 是 miniconda 3.13.13，缺 fastapi 等；脚本会自动改试 WorkBuddy 自带 Python 并打印 `[start] Python: ...`。若仍失败，看这行输出确认选中了谁；用 `set GACHA_PYTHON=C:\...\python.exe` 强制指定一个已装依赖的解释器，或手动执行一次 `python -m pip install -r requirements.txt`。**脚本不会自动下载** |
| 终端里能启动、双击不行 | 上面那条。同一台机器两个 Python，依赖只在其中一个；不要给 miniconda 装依赖，让脚本自己挑即可 |
| 语义包版本对不上 | `vendor/pydeps/` 里是本机 `.venv` 的 `onnxruntime 1.27.0` / `tokenizers 0.23.1`，与 `requirements.txt` 中的锁定版本无关；`start.bat` 用 `PYTHONPATH` 优先加载 vendor，跑 `--force` 可重搬 |
| 概念墙是空的 / 提示「先抽几次卡」 | 概念来自已生成图片的抽卡记录；`draws → generation_jobs → images` 一条都没有时自然为空（**刚跑完 `reset_db.py` 就是这样**）。先抽卡并生图，再点「刷新」；评分 / 收藏会立刻改变代表图 |
| hover 概念卡没出图 | 浮层是按需请求 `/api/concepts/cover?key=...`，浏览器 Ctrl+F5 强刷后再试；若该概念还没有出图，浮层显示「还没有出过图」。封面按 key 缓存，新图产出或评分后会失效 |
| 概念详情页只有 0 张 / 想看更多 | 首屏上限 50 张，`total` 更大时点「再加载最多 50 张」走 offset 分页；接口 `limit` 最大 50，传更大值会被拒绝 |
| 概念卡片点了过滤却没变化 | 卡片主体带的是数据库真实池类别（如 `服装:xxx`），先看结果区黄色告警与「⚠ 无匹配条目」；若该概念在当前配方里没有对应槽位，把作用池切到「全部卡池」或在「高级」里看生成的表达式。**点概念名是进详情页，不是加过滤** |
| 概念卡片图片不显示 | 封面走 `/api/images/{id}/thumb`。先确认该图记录还在、`data/thumbs/` 未被清理；外部风格锚点走 `/api/semantics/thumb?index=N`，源目录被移动时需重建索引 |
| 清空后真实模式出图失败（checkpoint 为空） | 配置回迁漏了：跑 `python scripts/reset_db.py --restore-config-only data/archive/<时间戳>/gacha.db`，把参数预设里的 checkpoint 迁回来；到设置页确认 checkpoint 是 `waiIllustriousSDXL_v170.safetensors` |
| 从旧归档库直接 upgrade 报错 | 旧库 `0001_initial` 与 v2 基线 `0001_v2_relational` 不兼容，**归档库只读**。要走 `reset_db.py` 清空重建，不要对归档库执行 `init_db.py` |
| 概念索引与关系表不一致 | 跑 `python scripts/rebuild_concepts.py` 全量重建（幂等）；手工改过库、批量恢复归档图之后必做 |
| 选了 `画师:bowalia` 抽完 prompt 里却没有画师 | 旧行为：配方没有画师槽位时，过滤只筛池、不新增槽位，条件被静默忽略。现在会自动补槽位并给出告警；若仍没生效，确认服务已重启加载新代码、浏览器已 Ctrl+F5 强刷 |
| 抽卡台还是上下堆叠 / 要一直滚动找控件 | 左右布局改在 `app.js` / `styles.css`，浏览器缓存旧版；Ctrl+F5 强刷。屏幕宽度 ≤1080px 会主动回落成单列，把窗口拉宽即可 |
